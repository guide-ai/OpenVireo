# Load question Yes: verified Save, then a separate Load choice (R-RX18, analysis only)

When **Load** in Pulsar Analysis finds an unsaved receiver recording, it asks the recovered question "You have not saved your current pulsar data! … Save current data now?" (flags 0x13). Until R-RX17 its **Yes** was disabled. R-RX18 enables it as a **web flow**:

1. **Yes** only opens the R-RX15 verified Save dialog for the recording the question was asked about. Yes chooses, writes and loads nothing, and it opens no file chooser.
2. **Choose file and save…** runs the R-RX15 Save unchanged: the browser picker, write, close and an exact, bounded, fresh read-back.
3. Only that flow's own attempt, ending in a genuine receipt of the same data object and generation, closes the Save dialog and opens a separate **Load choice**. The recording is still the current data, with its receipt, measurements and cursors. Nothing is loaded automatically.
4. **Choose recording to load…** is a fresh click. It opens a dedicated file chooser, and the chosen file goes through the existing strict read, SHA-256 and import. **Cancel** (the web default) keeps everything.

The data is a **model-generated capture of the receiver simulation, not observed CLEA data**. This is a **stricter web adaptation, not native equivalence**. No CLEA execution, emulation, native dialog or native trace was used. The tests check this implementation's web contract, not the original's behaviour.

Binary `CLEA_VEO.exe` SHA-256 `781bc9704b4674038267834a9ed21d502c455378d8fc9eb15a1653e20c52c54c`; accepted base `78ea2e184483cc33f14f9061ac2b77f516c97385`. Tags: [S] static listing (bounded GNU objdump copies reused from R-RX15..R-RX17, no new provider run), [I] analyst inference, [W] web policy. Listings, hashes and fact ids are in [PULSAR-LOAD-SAVE-PROVENANCE.json](PULSAR-LOAD-SAVE-PROVENANCE.json).

## Recovered facts (static)

- **E9-PROMPT** [S] `analysis-load-prefix-verified.asm` (SHA-256 `17148ae9…df34`), `0x56af38..0x56afbc`: the prologue installs its handler (`0x56af4f push 0x56b1ba`, `0x56af57 mov fs:[eax],esp`). When the list at `+0x80` is not empty (`0x492708`) and `+0x97` is 0 (`0x56af72`), the box `0x56b1d0`/`0x56b258` (flags `0x13`) asks. Cancel (2) → `0x56b192` cleanup. Yes (6) calls `0x56b36c` at `0x56afb7`. Any other answer, and the normal return of Yes, continue at `0x56afbc`.
- **E9-SELECTOR** [S] `analysis-load-after-save.asm` (SHA-256 `0e3a6c35…8aba`), `0x56afbc..0x56b098`: the OpenDialog fields are set and `0x56b00d` calls its virtual Execute. **No saved flag or Save success is tested before it.** A false result → `0x56b188`. The conditional warning on dialog byte `+0x64` bit `0x80` (`0x56b018..0x56b06b`, flags `0x13`) is **not ported**; its bit meaning and literals are not newly recovered. The reader `0x56a260` runs only at `0x56b093`, after the local accept byte `[ebp-0xd]` is set.
- **E9-CLEANUP** [S] same listing, `0x56b192..0x56b1c8`: the frame is unlinked at `0x56b197`; the handler entry `0x56b1ba` jumps to `0x4056e4`. The continuation after a thrown error is **not established**.
- **SAVE-WRITTEN** [S] `signal-write.asm` (SHA-256 `55069a74…bef7d`), `0x56a838..0x56a85d`: close `0x403bc8` and the I/O check `0x4030f8` precede `+0x97 := 1` (`0x56a848`) and the `+0x9a` name copy (`0x56a84f..0x56a85d`). The wrapper `0x56b36c` (`writer-caller-56b36c.asm`, SHA-256 `b56926da…40f5be`) and the reader (`signal-read.asm`, SHA-256 `7d8aa6ba…0f60`) are the listings already cited by R-RX15 and R-RX17; nothing new is claimed from them.

**Native vs web.** Natively the normal return of the Save wrapper falls straight into the OpenDialog, whatever the wrapper did, and a cancelled Save dialog returns normally. The web is stricter by explicit policy: only a verified receipt of this flow's own attempt leads on, and the file chooser needs its own fresh click. Not ported: the conditional warning, the thrown-I/O continuation, partial native read state and window effects.

## Web policy

- **WEB-RX18-01 Yes** [W]. Yes is enabled where the browser offers the save file picker (WEB-SAVE-01); otherwise it is disabled with the `insecure-context` or `no-api` reason, and No and Cancel work as before. There is no discard or download fallback. Pressed, it acts only for a single click (`detail ≤ 1`) in an active panel whose open Load question is the only modal, with no pending read, no other session or output in progress and no drag. `loadSaveOpen` then requires: the question is open; the panel presents data (`not-presented` otherwise, for example `No Data`); that data is the current object at the presented generation (`stale`); it is a memory capture with rows and no valid receipt (`not-memory`); no capture lease and no output claim (`busy`). In the same task the question closes with `'load-save'`, the Save session opens and the flow starts in `save`. Yes calls no picker and grants no chooser. The web default stays Cancel.
- **WEB-RX18-02 Save → ready** [W]. The flow's Save dialog is the R-RX15 dialog with an intro line. A Save click records its attempt token on the flow (`loadSaveAttempt`). When that attempt's read-back is recorded, `loadSaveVerified` requires the same flow id and attempt token, a live context (same generation, same data object, no lease) and a genuine current receipt (`pulsarWrittenCopy`) of the flow's data and generation, with the attempt's file name, which is not the `written` value the document held when the flow opened. Only then does the Save dialog close and the flow become `ready`, holding that receipt object. A spread or older receipt, another attempt, a same-generation object swap, a mutated sample or `+0 → −0` never makes it ready. **The saved flag is never the load authority**; it is used only to require unsaved data when the flow opens. A verified Save alone grants nothing.
- **WEB-RX18-03 Load choice** [W]. A dialog keyed by the flow id: the verified file name and byte count, a note that the recording is still current and that nothing has been loaded, **Choose recording to load…** and **Cancel** (default focus). If another modal is open when the receipt is recorded, the Save dialog closes under it and the Load choice waits until that modal closes. Cancel, Escape or a close request ends the flow; the capture, receipt, cursors and list stay, and focus returns to the Load control.
- **WEB-RX18-04 Dedicated chooser (CR1)** [W]. Choose is a fresh click (`detail > 1` ignored). It needs a live context, the flow's own receipt object still current, and no output claim. It takes a new invocation number, commits it with `flushSync` (which mounts a new hidden `<input type=file accept=".plr,.PLR">` keyed by `(flowId, invocation)`) and clicks that input in the same task, with no await. The input's change handler and its native `cancel` listener each capture their own `(flowId, invocation)`. A selection is accepted only for the flow's outstanding invocation; anything else (an older node, a cancelled or emptied invocation, another flow) is silent. An empty selection or the input's standard `cancel` event consumes the grant and returns to `ready`. Choose again supersedes the older invocation, and the older node leaves the DOM. Window blur never cancels. A browser that never fires `cancel` keeps the grant until Cancel, Choose again, a hide or a context change; this is bounded and explicit, not detected.
- **WEB-RX18-05 Read and commit (CR2, CR3)** [W]. An accepted selection moves the flow to `reading` (the dialog closes and the pending-read gate applies) and runs the shared reader with the flow's generation. After `arrayBuffer` and after the SHA-256 promise, the read must still be this flow's read (otherwise it is **silent**: no late-read text, no change to a newer read, status or flow) and its context and receipt must still be current (otherwise it fails as `superseded` and the flow ends). The commit is one synchronous step: `loadSaveImport` rechecks the flow inside the shared update and calls the unchanged `importPulsarRecording` with the flow's generation; then the flow ends, the new generation is adopted and the ordinary `pulsarLoad` runs. As with No, the import drops the old receipt, the origin becomes file data with its SHA-256, the measurement list is kept and the view resets.
- **WEB-RX18-06 End of the flow (CR6)** [W]. Save Cancel (or Escape) ends the flow: the data, any receipt and the list stay, and a later Load → No is a new explicit choice under the existing rules. A bad file, a size or read error, Cancel reading, a hide, a busy state or a context change end it too; nothing is replaced automatically and the old dedicated input stays invalid. A failure of the flow's own read (a bad, oversized or unreadable file, a superseded context or a refused import) also clears that flow's status line, so no stale reading or Choose notice remains; the rejection alert carries the reason. An obsolete flow read stays silent and clears nothing (this is not the ordinary path's late-read policy, which is unchanged). After the flow ends, the ordinary rules apply: saved data loads through the ordinary chooser without a question (RX18-35), unsaved data asks again.
- **WEB-RX18-07 Guards** [W]. While a flow exists, every core action is refused (`blocked-modal`); in `save`, `ready` and `choosing` it is a modal session (arming refused, newer-data adoption held); in `reading` the pending-read gate applies. Export, Append, raw Download, Save, the imported-file Download and the generic Load chooser refuse while it exists (checked on refs, not only by disabled HTML); a change delivered to the generic input is refused unread. The R-RX15 output claim and the R-RX16 shared claim are unchanged: they are released only in the attempt's `finally`, with no timeout or forced release. In `reading` no dialog is open, so a refused core action says the chosen recording is still being read (wait or Cancel reading) instead of "Finish the open dialog first."; the outcome stays `blocked-modal`. A refused Yes (for example `No Data`) is also shown in the Load question's own status line (`role="status"`, `aria-live="polite"`); the question stays open and No, Cancel and Yes keep their rules.
- **WEB-RX18-08 Hide and unmount** [W]. A hide or busy state ends the flow in every phase and withdraws its chooser grant. A Save attempt that was running keeps its `abandoned` notice; its session stays as a standalone Save dialog, so a later verification never reaches the Load choice. A pending flow read is cancelled (its late completion is silent). An **unmount** is handled in a layout cleanup, so the panel is dead in the commit that removes it: it bumps the read and Save tokens, clears its own running Save and sets no state of the panel. Only these continuations are guarded by it (the append, export and raw download continuations are not covered by this statement):
  - A pending ordinary or flow read (`readPlr`) finishes inert after its `arrayBuffer` or SHA-256 await: no import, adoption, digest, flow change or status, including no late-read text and no read-error text.
  - A pending Save attempt is abandoned: it aborts a stream that is still open and records no receipt. Its exact `('analysis', token)` output claim stays held until its own `finally`, after that stream cleanup settled; the unmount forces no release.
  - The panel's modal/read activity on the surviving owner is reset to idle in the same commit (also when the panel switches to another owner), through that owner's stable `update`. The activity is not keyed by panel: this **assumes one analysis panel per owner**.

## Gaps and limits

| # | Limit | Effect |
|---|---|---|
| L1 | Conditional warning (`+0x64` bit `0x80`), thrown-I/O continuation, partial native read state, window effects | Not ported; no native success test or error path is invented. |
| L2 | Native Save wrapper `0x56b36c`, OS picker, physical durability, x87, GDI, locale | Not claimed; the receipt is historical (R-RX15). |
| L3 | A browser without the input `cancel` event | The grant stays until Cancel, Choose again, a hide or a context change. The App test dispatches `cancel` itself; native delivery is not witnessed. |
| L4 | A provider promise that never settles | Keeps the shared output claim held (R-RX16 L4); the Load choice cannot open Choose meanwhile. |
| L5 | Real unmount | The App keeps the panel mounted, so no App navigation witnesses it. Witnessed only by a test-only host (`tests/fixtures/pulsar-load-save-unmount-host.ts`) that keeps its own dataset owner mounted, with a synthetic capture, a synthetic Save picker and Playwright's intercepted chooser: no native or OS dialog, no user file, no browser `cancel` delivery. That no status is written after an unmount is not observable there; it rests on the guard in the code. The activity reset assumes one analysis panel per owner. |
| L6 | A dataset change during a held flow read | Not reachable from the App UI while the flow holds the gate; checked by the pure core tests (`loadSaveSelected`, `loadSaveReadLive`, `loadSaveImport`). |
| L7 | Web default Cancel in the question and in the Load choice | Declared web choice; the native default is not claimed. |
