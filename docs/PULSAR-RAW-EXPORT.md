# Raw .PLR download of the current memory capture (R-RX14)

Pulsar Analysis can download the receiver recording held in this tab as a new `.PLR` file, in the line layout of the recovered PLR writer `0x56a518`. The button is **Download capture as .PLR…**, shown only for memory data. This is a **web export**. It is not the original Save:

- A download never changes the saved status. Unsaved data stays `Data Not Written to File`, and an existing verified copy is kept. No file origin or name is recorded, and the dataset generation does not change. R-RX15 adds a separate **verified Save** that can mark a memory capture as written ([PULSAR-SAVE-VERIFIED.md](PULSAR-SAVE-VERIFIED.md)); a download here never sets that status.
- The receiver Save **Yes** and the analysis Load **Yes** stay disabled.
- The downloaded data is **model-generated by the receiver simulation, not observed CLEA data**. The PLR layout has no field for that origin. Only the fixed file name `openvireo-model-capture.PLR` and the dialog note carry the warning. A re-imported copy is ordinary file data, and its origin label is lost.

Native equivalence is not established. No CLEA execution, emulation or native trace was used, and no original PLR written by the writer is available. The tests check this implementation's contract, not the original's output.

Binary `CLEA_VEO.exe` SHA-256 `781bc9704b4674038267834a9ed21d502c455378d8fc9eb15a1653e20c52c54c`. Tags:
- [S] static listing;
- [I] analyst inference;
- [W] web policy.

The listing paths and hashes are in [PULSAR-RAW-EXPORT-PROVENANCE.json](PULSAR-RAW-EXPORT-PROVENANCE.json).

## Modules

- `src/core/pulsarRawExport.ts`: the byte builder, its refusals, the loss summary and the dialog session. It is pure TypeScript.
- `src/core/pulsarRecording.ts`: the reader bounds are exported as `PLR_VALUE_BOUNDS`. Reader behavior is unchanged. The existing `formatFixed` and `admitPlrRecording` are reused.
- `src/components/PulsarAnalysis.tsx`, `src/components/PulsarMessages.ts`: presentation only.

## Recovered writer (static)

Header offsets below are relative to the header base (data object + 4, `esi` in the listing).

- **RAW-WRITE-01** [S] `0x56a518..0x56a8be` (`signal-write.asm`). The writer receives the data object in EAX and a file-name string in EDX. It writes these lines:
  1. `0x56a5a2..0x56a64d`: the literal `0x56a8c0` `'`, then the ShortString name at +0 (concatenation caps `0x29`/`0x2b`), then the literal `0x56a8c4` `',`. These are followed by `0x40ac14` of the Word at +0x29, the literal `0x56a8d0` `,`, and `0x40ac14` of the Byte at +0x2b. The pieces are joined by `0x4061c4` (count 4), written by `0x4065e0` and ended by `0x40460c`.
  2. `0x56a65a..0x56a6ca`: for i = 0..2, a cell i ≤ Byte +0x2b gets `0x486268` with digit count 2 on the 10-byte value at +0x2c + 10·i. Any other cell gets the AnsiString `0x56a8dc` `0.0`. Cells are separated by `,` (except after i = 2).
  3. `0x56a6cf..0x56a747`: the same rule with digit count 3 on the 10-byte values at +0x4a + 10·i.
  4. `0x56a74c..0x56a7ad`: digit count 8 on +0x68, `,`, and digit count 5 on +0x72.
  5. `0x56a7b2..0x56a836`: `0x492628` and then `0x492634` on the list at object +0x80. Each of the three Doubles of the returned item is loaded and stored as a 10-byte value (`fld qword` / `fstp tbyte`), and formatted with digit count 3, separated by `,`, before a line end. The loop repeats while `0x49271c` returns zero.

  At R-RX14 the helper bodies `0x492628`, `0x492634` and `0x49271c` were not in evidence, and "every row once, in list order" was an inference [I]. R-RX15 later recorded SAVE-ROWS [S, I] and SAVE-EMPTY [S] ([PULSAR-SAVE-VERIFIED.md](PULSAR-SAVE-VERIFIED.md)): a well-formed non-empty list is traversed head to tail once. No runtime row count is witnessed.
- **RAW-WRITE-02** [S] `0x56a848..0x56a85d`: byte +0x97 of the object := 1, and the file-name argument is copied to object +0x9a: `0x56a84f lea eax,[edi+0x9a]`, `0x56a855 mov edx,DWORD PTR [ebp-0x4]`, `0x56a858 mov ecx,0xff`, `0x56a85d call 0x4060cc` [S]. Reading the `0xff` argument as a bounded ShortString copy is an inference [I] (the callee is not re-inspected); the web name bound is a [W] policy with no ANSI-byte equivalence. Object +0x96 is not written by this routine's own instructions. Transitive effects of its callees are not established. **Not ported**: the R-RX14 Download never sets `+0x97` or `+0x9a`. R-RX15 adds a separate web counterpart (a verified-copy receipt), not a port of this routine ([PULSAR-SAVE-VERIFIED.md](PULSAR-SAVE-VERIFIED.md)).
- **RAW-WRITE-03** [S]:
  - `0x47b7a8` is called with DX = `0xfff5` before the output and with DX = 0 after it. The second call is only on the straight path. What these calls do is not claimed.
  - The SEH frame `0x56a8b1` releases the locals.
  - No partial-file rollback appears in the listing.
  - **Not ported.**
- **RAW-FMT-01** [S, I] `0x486268` (`formatters-486268-4863a0.asm`) calls `0x40cf28` with AL = 2, EDX = 18, ECX = the caller's digit count, and the 10-byte value on the stack. Reading this as `FloatToStrF(value, ffFixed, 18, digits)` is the existing inference [I]. The host decimal separator, the rounding inside `0x40cf28` and the sign of a rounded zero are not established.
- **RAW-LIT-01** [S] `requested-literals-and-constants.json`: `0x56a8c0` `'`, `0x56a8c4` `',`, `0x56a8d0` `,`, `0x56a8dc` `0.0`.
- **RAW-CALL-01** [S] `0x56b36c..0x56b678` (`writer-caller-56b36c.asm`). The caller of the two writer sites `0x56b5ce` and `0x56b5eb` loads the object pointer `0x5bcca0` into EAX before each call. The routine's steps are below; the helpers are named only by address.
  1. It calls `0x492708` on the object's list. A nonzero result shows `0x47e09c` with the literals `0x56b67c`/`0x56b68c` and flags `0x30`, then exits.
  2. At `0x56b3e1..0x56b3fc` it calls `0x44d9f4` with EAX = the dialog object (form `+0x37c`) and EDX = the dword at form `+0x5cf` (the field step 6 writes). It then calls `0x405e84` with EAX = dialog `+0x78` and EDX = the literal `0x56b6b0`. After that it builds a candidate name from up to 8 characters of the object name, or from `0x56b6cc` when that is empty, with `0x56b6d4`, a counter from `0x40ac14` padded with `0x56b6d8`, and `0x56b6dc`.
  3. It loops while `0x40b224` on the combined path returns nonzero.
  4. It calls a method at VMT +0x3c of the dialog object `+0x37c`. When the result is zero, the loop ends without writing.
  5. When bit `0x80` of dialog byte +0x64 is set, `0x47e09c` runs with `0x56b6ec`/`0x56b798` and flags `0x23`. A result of 2 ends the loop; 6 repeats it; 7 calls the writer. When the bit is clear, the writer is called directly.
  6. At the end, the result of `0x40b514` on the local string at ebp−0x8 is stored in form +0x5cf.

  The meanings of `0x492708`, `0x44d9f4`, `0x405e84`, `0x40b224`, `0x40b514`, dialog `+0x78`, the dialog method and the bit `0x80` are not bound by these captures. Other callees in the listing are not enumerated here. The caller literals are not decoded here. **The whole caller is not ported.** None of it is needed for the separate explicit download. R-RX15 later decoded the caller literals and recorded static facts for `0x492708`, `0x40b224`, `0x40b514` and the dialog class ([PULSAR-SAVE-VERIFIED.md](PULSAR-SAVE-VERIFIED.md)); native Save Yes stays gated.

## Web policy

- **WEB-RAW-01 Scope** [W]:
  - Only the current memory capture, and only from Pulsar Analysis.
  - Not for an imported file (its exact-byte **Download original recording bytes** is unchanged), a cleared header or no data.
  - No receiver, Load or Results-Save path is changed. The native CSV Save stays gated and separate.
- **WEB-RAW-02 Gates** [W]. The opener follows the Export conditions, except that no measurement is needed:
  - the panel is active and shown;
  - no dialog is open, here or in the host;
  - no file read is pending;
  - no drag or capture lease is in progress, and no newer data is waiting;
  - the presented data is the shared current memory object.

  The dialog is a modal session:
  - the main region is inert and core actions are refused (`blocked-modal`);
  - a PLR change is refused unread;
  - adoption of newer data is held;
  - receiver arming is refused while the session exists, also when a hidden route has closed the dialog (the session is kept and reopens).

  Download checks, in order:
  1. the request is not in progress;
  2. the dialog is presented, active and with no foreign modal;
  3. readiness (no read, lease or core modal), else `not-ready`;
  4. the same data object and generation as at opening, else `stale`;
  5. a fresh build of the bytes, because the Float64Array is mutable. A build problem is reported. A build that differs from the shown preview is `stale` and is not refreshed silently.

  The shared output claim is taken before the Blob, object URL and link calls, and released only after the success or failure handling. A Download or Cancel that reenters from inside the link click therefore does nothing. A browser error revokes the URL, keeps the session and shows a failure, so the learner can retry. A requested download ends the session and returns focus to the opener.
- **WEB-RAW-03 Refusals** [W]. The first problem wins and nothing is repaired:
  1. `not-memory`.
  2. `no-rows`, `too-many-rows` (over 65536), `samples-shape`.
  3. The name: `name-text` (outside printable ASCII), `name-apostrophe` (the reader ends the name there), `name-length` (over 40), `name-reserved` (`No Data`). An empty name is written as `''`.
  4. `aperture` (not an integer 0..65535) and `highest` (not 0, 1 or 2).
  5. For recorded receivers (index ≤ highest): `metadata-missing` (null) and `metadata-range` (non-finite or outside the reader bounds). The same applies to the start and the interval. Inactive cells are never read and are written as `0.0`.
  6. `gain-zero`: a recorded gain whose 3-decimal text reads back as 0. This covers exact 0, −0 and values that round to zero. The reader would replace it with 1, a silent change of effective metadata.
  7. `interval-zero`: the 5-decimal text is not > 0.
  8. `sample-range`, with the 1-based row and the column.
  9. `channel-erased`: a recorded channel with a nonzero sample whose samples all become `0.000`. This is a conservative web policy. Exact-zero channels and inactive columns are accepted.
  10. `too-large` (over 2 MiB, computed before assembly).
  11. `profile`: the strict reader does not admit the bytes with exactly the written lexemes, the CR LF ending, no zero replacement on a recorded gain and the same rows.
- **WEB-RAW-04 Numbers** [W]:
  - Every value goes through the existing `formatFixed`, which is `Number.prototype.toFixed(digits)` on the binary64 value. This rounds the exact binary value, and a tie goes to the larger magnitude. The decimal mark is always `.`, and a rounded zero has no `-`.
  - Digits: frequency 2, gain 3, start 8, interval (seconds) 5, sample 3.
  - The dialog lists, before the download:
    - the header fields whose text reads back differently;
    - the number of samples that change;
    - the number of nonzero samples that become `0.000`;
    - the `0.0` policy for unrecorded receivers.
  - The values in memory never change.
  - No native byte, x87, FPU or locale equivalence is claimed, and nothing is claimed about native exponent switching or rounding inside `0x40cf28`.
- **WEB-RAW-05 File** [W]:
  - The fixed name is `openvireo-model-capture.PLR`, with media type `application/octet-stream`.
  - Lines end with CR LF, including the last one. The runtime line-end flag of `0x40460c` is unknown.
  - All three sample columns of every row are written.
  - The request is a fresh download. Nothing is overwritten or appended, there is no host path, and whether the browser stores the file is not confirmed.
  - The status says that a download was requested, not that a file was saved.
- **WEB-RAW-06 State** [W]:
  - The download handlers (open, request, cancel, failure) do not call `shared.update` and do not change the analysis core state, the generation, data, saved flag, origin, file name, measurement list or storage. Separately, while the session exists it is one input of `modal`. The existing layout effect reports `modal` to the shared dataset (`setPulsarAnalysisActivity`, `analysis.modal`), as Export and Append already do. That activity flag refuses receiver arming (WEB-RAW-02). It does not change the generation, data, saved flag, origin or file name.
  - The source object and its Float64Array are never written to.
  - A failed request changes only the dialog session.
  - R-RX15: the download handlers do not read or write `doc.written`. They only choose the status text: when the current data has a valid verified copy, the dialog and status say that the recording keeps it. The R-RX15 Save reuses this module's bytes, refusal order and session type (`purpose: 'save'`, `save` notice); see [PULSAR-SAVE-VERIFIED.md](PULSAR-SAVE-VERIFIED.md).

## Residual risk

- A re-imported copy is ordinary file data: Properties then shows the browser file name, and Load no longer asks the unsaved-data question for it. The model origin survives only in the file name chosen by the web, which a learner can rename.
- Rounding to 3 decimals can change or zero individual samples. The counts are shown before the download, and a channel that would be erased entirely is refused.

  These are web contract checks, not native witnesses.
