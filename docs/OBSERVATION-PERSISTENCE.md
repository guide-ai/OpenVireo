# Observation notebook: separate web persistence

Confirmed observation results now survive reloading in the same browser/origin when local storage is available. **Export observation notebook** produces a portable JSON backup; **Restore observation notebook** validates it, previews every row and requires explicit replacement confirmation. Cancel/Escape leaves the notebook and its browser copy unchanged. Draft edits are never saved.

This is a new **OpenVireo observation notebook**, version1, policy `original-practice-id-sha256-web-v1`. It is **not a native CLEA `.DAT` file** and is **not included in existing investigation/classification JSON or CSV**. Save those files separately for the rest of your work. Restoring an old investigation/classification file retains this separate notebook; no automatic conversion of free answers or confirmed classification/width records occurs. Passing either format to the other restore control is rejected. Future notebook versions are rejected rather than guessed or silently downgraded.

## Try locally

1. Open `http://127.0.0.1:5173/#classification`. Choose an original **Practice object**, then **Open observation results**. Enter your own type and short remarks and **Record observation result**. The browser-saving status must say saved.
2. Reload the page. The confirmed row and reuse/append option remain; an unconfirmed edit does not. **Edit observation result 1** still follows the recovered canonical type conversion, including its documented display quirks.
3. Click **Export observation notebook** and retain `openvireo-observation-notebook.json`. This file preserves exact packed type codes, literal remarks/spaces, original source ID/name/SHA, stable ordered row IDs and reuse/append mode. In particular, export/restore never reparses a lossy displayed type label.
4. Click **Restore observation notebook**, choose that file and review the current/incoming row counts and all incoming rows. **Cancel notebook restore** keeps existing work. **Replace observation notebook** replaces the complete notebook and saved mode; it does not merge, renumber or alter existing investigation/classification work. An empty notebook requires the same explicit confirmation.
5. Try a malformed JSON, unrelated investigation file, future version, changed source SHA, duplicate ID or unsupported remarks. It must report rejection and retain current memory/browser work. Validated identity means association with the admitted source bytes, not authenticity of an imported pupil response.
6. Repeat in mobile layout. The restore dialog scrolls, notes wrap and controls support touch/keyboard. Navigation/source/file activity and cancelled reads invalidate stale restore completions and confirmation buttons.

## Storage and recovery policy

The separate key `openvireo.observation-notebook.v1` uses the exact portable envelope in origin-scoped `localStorage`. Only confirmed rows and explicit reuse/append changes are written. This small100-row/128KiB bound does not require IndexedDB, a Worker, service or network request. The browser copy is convenience storage, not a portable backup: private browsing, clearing site data, changing protocol/host/port, browser policy or quota can make it unavailable. There is no encryption or secret-storage feature; do not use these short exercise notes for secrets.

An unreadable local copy is preserved and automatic writes stop. **Download unreadable local copy** saves its exact text for recovery; export any new in-memory work too. Restoring a valid notebook requires review/confirmation before intentionally replacing the old browser copy. Storage read/write/quota failures are visible and leave confirmed in-memory work exportable; a success notice for restore does not replace the separate browser-saving warning.

Another-tab storage events stop automatic saving instead of silently adopting or overwriting a changed copy. A compare-before-write and read-back check also detect a changed value. Export the current unsaved notebook, then reload or explicitly restore the chosen file. A change after restore preview rejects confirmation without changing memory or the browser copy. `localStorage` has no atomic compare-and-set across simultaneous tabs: this check cannot guarantee serializable writes under perfectly overlapping processes. Portable exported files remain the primary recovery path.

## Strict representation and native boundary

The envelope has exactly `format`, `version`, `policy`, `mode` and `notebook`; the notebook has exactly `records`. Each row has exactly `id`, `source`, `spectralCode`, `remarks`; source has exactly `id`, `sha256`, `objectId`. IDs must be strictly increasing positive safe integers below `Number.MAX_SAFE_INTEGER`. Gaps are preserved. The existing100-row limit,36printable Windows-1252-byte remarks, permitted generic integer code fields and exact25original-practice identity triples are revalidated before use. Decoding is fatal UTF-8 with both declared and actual128KiB limits. Restored sources are rebound to immutable verified practice tokens, never arbitrary imported/acquired authority. No cached numerical result, grade, JD, position or photometry is accepted. [Deletion recovery](OBSERVATION-DELETE.md) now adds a separate local recovery key without changing this envelope;normal notebook export contains current rows only,while Export deletion recovery saves the complete before-state as another notebook-v1 file.

[Static provenance](OBSERVATION-PERSISTENCE-PROVENANCE.json) captures the original data writer `[0x547b0c,0x547e62)` and reader `[0x549aa8,0x549cff)`. The writer chooses `.DAT`, sets typed-record size `0x90`, rewrites the file and loops current list records through0x4043b8. That helper passes the record-size count and data pointer to the WriteFile import and checks bytes written. No application header write is observed in this captured writer. The reader resets with size0x90, offers append/clear/cancel and appends full records; the first record's display-kind+0x5e controls formatting. Adjacent text-load paths have exercise/options compatibility checks and remain a separate codec recovery.

The current web notebook owns only manual type/remarks and verified source identity. It has no owned native date/timeDouble,RA/DecExtended,five photometryExtended,display-kind,redshift/velocitySingle values required by the complete144-byte record. Exporting such a native record would require inventing missing fields. [Read-only DAT inspection](NATIVE-OBSERVATION-RESULTS.md) now reads stored fields and copies imported bytes unchanged;no editable merge or reconstructed DATwriter is offered. Full text/ACP/Extended/float/error/partial-record semantics and an independent original-writer output witness remain absent; original execution/emulation is prohibited. Static layout/calls and chosen web roundtrips do not establish native runtime compatibility. Existing original files/hashes remain unchanged.

Rows from the earlier in-memory-only version were never contained in its session files or browser storage;closed/reloaded pages from that version cannot be reconstructed by this update. No missing earlier row is invented.
