# Radio Simulation Options: the nine numeric fields (R-RX9)

R-RX9 ports the full TRadiOptsDlg form (VMT `0x5a7c84`) of the original program inside the existing Radio configuration card ([RADIO-ACCESS-OPTIONS.md](RADIO-ACCESS-OPTIONS.md)): the nine numbers with their recovered activation display, the ordered OK that stores flags first and numbers one by one with no rollback, and the whole-snapshot Cancel. The form exists only under an explicit in-memory **numeric authority**; at startup the authority is absent and the R-RX7/R-RX8 Access-only form, its OK and the panel's own Limit Slewing scenario are unchanged. At each Preferences close the record copy (env+0x2e95) is projected onto the consumers that are already ported: the antenna options, the receivers' live options view and the control panel's dish diameter.

- Core: `src/core/radioOptionsNumeric.ts` (numeric policy, imports nothing), `src/core/radioAccessOptions.ts` (authority, record, child, transitions; its only import is the numeric module), `src/core/radioOptionsProjection.ts` (pure projection), `src/core/radioReceiverSession.ts` (`copyReceiverLiveOptions`).
- UI: `src/components/RadioAccessOptions.tsx` (card section, full dialog and failure box), `src/components/RadioTelescopeRoute.tsx` (projection commit and ownership guards), `src/components/RadioReceiverWindows.tsx` (`commitLiveOptions`), `src/components/RadioControlPanel.tsx` (`managedDiameter`).
- Tests (written, run by the coordinator): `src/core/radioOptionsNumeric.test.ts`, `src/core/radioAccessOptions.test.ts`, `src/core/radioOptionsProjection.test.ts`, `src/core/radioReceiverSession.test.ts`, `tests/radio-simulation-options-app.spec.ts`.
- Provenance: [RADIO-SIMULATION-OPTIONS-PROVENANCE.json](RADIO-SIMULATION-OPTIONS-PROVENANCE.json).

Tags: [S] static disassembly, [D] DFM resource decode, [I] inference, [W] web adaptation (not native behaviour). Tests are evidence of this implementation's contract, not an oracle for the original program. Nothing was executed or emulated; this uses already recovered, REA-derived static evidence and the coordinator's bounded static inspection, with no runtime oracle.

The new dialog lives in `RadioAccessOptions.tsx` rather than a separate component file: the presentation-catalog audit (`src/i18n/coverage.test.ts`) pins the inventory of `.tsx` files, and that test is outside this increment.

| Function | Effect |

OK under an authority: (1) all ten flags, with the read-only controls written back from the activation snapshot they display and `0x93b` := 5 or 4; (2) the nine numbers in OK order, each stored as soon as it converts. The first failure returns `radio-ok-numeric-failed`: root holds the flags and the prefix, the child stays open with `failure = {field, position 0..8, kind, reason, text}`, `lastChildOk` is unchanged. Success closes the child and sets `lastChildOk := true`. Unknown properties are kept by reference. Nothing is projected at child OK.

## Web policies [W]

- **WEB-RSO-AUTH-01 Numeric authority.** `absent` (startup), `compiled-branch` (two card buttons, "Use built-in defaults, Sound Sync 0.765" for `0x48c394` true and "… 0.92" for false) or `supplied` (tests). The branch is never inferred from the browser, the operating system or WEB-RX-CAD-01's 40 ms reading; the card says the classroom host branch is unknown. The opt-in is refused while a surface is open, once an authority exists, when root or env is no longer the untouched `{accessPulsarList: false}`, and when a live consumer differs from the chosen record: the antenna options (for example the panel's Limit Slewing scenario turned on), the receivers' live options, or the control panel's dish diameter, which must be 100 (startup has it unsupplied: the refusal names the panel's "Use compiled defaults" preset or entering 100). This is a web policy on observable in-memory values; it never recovers or assumes a classroom or host state and never sets a value itself. Success replaces root by the frozen 19-key compiled record and env by a copy; the gate, menu history and last child result are untouched. One-way; reload resets it. Sound Features true enables no audio. Focus [W]: a successful opt-in whose button had focus (the button is removed) moves focus once to the numeric section heading; no move when the route is hidden, a project operation runs, the card's box or dialog, another radio surface or a foreign `<dialog>` exists, or focus is already elsewhere, and none on a later render. A refused opt-in keeps the button and its focus.
- **WEB-RSO-OWN-01 One aperture owner.** env+0x2e95 + record+0x916 is env+0x37ab, the panel's `RadioEnvironment.dishDiameterMeters`. Under an authority the radio options own it: the panel's diameter editor, Apply, Cancel and Clear are disabled with the note "Change antenna aperture in Radio Simulation Options" (`managedDiameter`, whose handlers also re-check a ref), and the route's environment handler shields every legacy write (editor, Clear, the compiled-defaults preset, a same-task or programmatic click) by keeping the current diameter; the dome byte, the access option byte and the other Window items stay usable. While managed the disabled editor shows the current diameter; an earlier draft's invalid mark and alert are withdrawn at the hand-over, and its unapplied text is neither shown nor applied. The antenna options are owned the same way: the panel's Limit Slewing scenario is not offered and its handler ignores a late apply. The receiver keeps its own web domain (dish 0..10000) and reports a refused projection explicitly. Absent: all of this is exactly as before.
- **WEB-RSO-NUM-01 Grammar.** Draft texts are any string up to 64 UTF-16 units; a longer edit is refused and named (no `maxLength`, so a paste is never truncated). OK admits `^[+-]?(\d+(\.\d*)?|\.\d+)([eE][+-]?\d+)?$` in ASCII, `.` only, no trimming, no Infinity/NaN/hex. Other texts fail as `grammar` under the recovered caption, whose note says the original StrToFloat grammar and locale are not recovered (some refused texts may have been accepted natively, and the reverse).
- **WEB-RSO-NUM-02 Integers.** The exact decimal value (BigInt: sign, digits, power of ten, decided by order of magnitude before any power) is rounded half to even, required inside Int64 (`int64-range` otherwise, a web limit whose native outcome — FISTP invalid, exception class — is unknown), then stored as its low 32 bits (Aperture, Base Slew, Background, signed) or low 16 bits (Sample Rate, unsigned). Half-even is inferred from the Delphi default control word $1332 (RC = 00); the runtime control word is not observed. This is a chosen web policy: it is not claimed to reproduce native StrToFloat accumulation or the active FPU for every integer text, and the low-bit projection is not native range validation.
- **WEB-RSO-NUM-03 Singles and horizon.** Singles: `Number(text)` (finite, else `binary64-range`) then `Math.fround` (finite, else `single-range`); signed zero, subnormals and underflow are kept; the decimal → binary64 → binary32 double rounding can differ from the native decimal → Extended → Single path and is declared. Sound Sync: the Single, then values above Single 1.0 become 1.0, no lower clamp. Horizon: degrees × the binary64 value of Extended `0x5a9768`, stored as binary64 (natively a 10-byte Extended), refused (`degrees-range`) when its degree display would not be finite; `10 × D2R` equals the compiled horizon's binary64 bits, so an untouched OK keeps it (not claimed for native Extended).
- **WEB-RSO-FMT-01 Display.** Int32 as `String`, the Word unsigned; Singles and the horizon degrees (radians × the binary64 value of Extended `0x5a93ec`) with `toFixed(digits)` (ties away from zero on the exact binary value, −0 as 0) below 1e18, otherwise `toExponential(17)`, which the grammar re-parses. Digits in OK order: 1, int, int, 5, int, 2, int, 2, 1. The native precision-18 FloatToStrF boundary and exponent form are not claimed. A Single shown with fewer digits round-trips lossily (for example `fround(0.123)` → "0.12"), as the native display would.
- **WEB-RSO-ERR-01 Failure box.** An `alertdialog` above the dialog. `grammar`: the recovered caption "Non-Numeric Value!" with an OpenVireo body; its note quotes the helper input literal `0x5a9780` and says the helper's final wording is not established. `web-limit`: the web title "Browser limit", labelled as OpenVireo's with an unknown native outcome. The body names the field (DFM label), the text, what OK already wrote (the Options group, both groups, Access Pulsar List and the earlier fields) and that the failing and later fields keep their values. Enter or Escape closes only the box (held keys ignored); focus returns to the control that chose OK. No re-snapshot after the box: the reactivation timing after `0x47e09c` is unresolved, so Cancel restores the first activation snapshot.
- **WEB-RSO-KEY-01 Keys and focus.** On open, HorzEd has focus with its text selected. Tab stays inside (the nine fields in DFM order, Limit Slewing, Fast Slewing, Access Pulsar List, OK, Cancel). A fresh Enter in a field or check box chooses OK (DFM OKBtn `Default = True`); Enter on a button activates that button; Escape is Cancel and stops there; held Enter/Escape are ignored. The read-only check boxes, both groups and Files.../Site... are disabled. Presentation follows WEB-ACC-PRES-01: hidden route, project operation, foreign `<dialog>`, an arriving antenna surface or receiver box suppress it with its drafts and failure kept.
- **WEB-RSO-PROJ-01 Projection.** Only right after a committed `preferences-closed-ok` or `-cancel` under an authority (the recovered root → env copy point), synchronously, consumer by consumer, on each owner's latest state; each parent close re-projects the whole env (idempotent). Nothing projects at child OK, at opt-in, or on route show/hide, and a refused consumer is never retried automatically. Antenna: refused for Telescope Type Arecibo (never collapsed to Fully Steerable), Test Mode (`0x940` would switch an unported mode) or a latched manual hold; otherwise the six mapped fields replace the current ones (latitude kept), reported as unchanged or applied with the changed fields and `radioLabProfileIssues` (an unsupported profile is applied and then refused at use by the panel, never clamped); the antenna state, its rate index, rate and timers are untouched (RA-06/RA-10 and `radioLabRateIssues` decide a stale rate). Panel: the diameter := `aperture916` (every Int32 is shape-valid there), other inputs kept. Receiver: the five-field view with provenance `supplied-record`, unchanged when equal, `refused-domain` outside `radioReceiverOptionsIssue`, otherwise `copyReceiverLiveOptions`, which is refused while the close box or a Record dialog is open and while the session holds the Record capture lease or an armed capture (`record-lease-held`, so a Receive header never mixes options), and is committed by compare-and-swap. It changes only `bank.options`: open receivers keep their FormCreate caches (gain, background, temperature, area); their aperture and beam texts change at the next display refresh (Receive start, mark Clear, mount paint); receivers created later take the new values; no Open, reseed, reassociation or paint runs. The card reports the antenna, receiver and panel outcomes separately, so a changed stored record is never shown as a successful receiver apply.
- **WEB-RSO-SAVE-01 Session only.** The authority, record, drafts and reports are not part of Save investigation, storage or any export; reload resets them.

Not applied (shown on the card): Sound Sync Factor, Sound Sample Rate and Sound Features (no audio exists), Plot Pulsar Positions, Write Hot List File, Exact Pos for Hot List and Pulsar Identification.
