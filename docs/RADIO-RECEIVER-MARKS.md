# Manual receiver marks and time readout R-RX3 (Radio route)

Each receiver window of the silent monitor ([RADIO-RECEIVER-MONITOR.md](RADIO-RECEIVER-MONITOR.md)) now has the two recovered manual marks: a first and a second vertical line on the display, each with a time label `column × sweep seconds ÷ N`. They are placed on a stopped sweep with the mouse, touch, pen or the keyboard, and cleared with the recovered Clear priority.

The marks read times on a **modelled display**. They are not measurements, read no catalog value (no period, pulse or intensity is measured automatically), are temporary (not in Save investigation; reload, Close and Receive reset them) and are not written to PLR. Record, Identify, PLR writing, Align, audio, automatic period/dispersion and any session or investigation schema change remain excluded. This does not complete Radio or change any of the 58 capability counts. Native equivalence is not established: no CLEA execution, emulation or native trace was used, and the tests check this implementation's contract.

Binary `CLEA_VEO.exe` SHA-256 `781bc9704b4674038267834a9ed21d502c455378d8fc9eb15a1653e20c52c54c`. Evidence tags: [S] static listing, [D] DFM/resource default, [I] analyst inference, [W] web policy. Paths and hashes are in [RADIO-RECEIVER-MARKS-PROVENANCE.json](RADIO-RECEIVER-MARKS-PROVENANCE.json). The static package is `/tmp/clea-static-research/radio-rx3-mark-contracts-20261024/` (CONTRACTS.md/json, ACCEPTANCE-CASES.json, capture audits, STATIC-VERIFICATION.json).

## Ported contracts (CONTRACTS.json M1–M6)

- **M1 time label** [S] (`0x575684..0x5757fa`). Admits signed `0 ≤ x ≤ N` (N = Word `+0x51d` = 400), so `x = N` is labelled although the trace store's last index is 399. `t = x · snapshot / N` with the sweep snapshot `+0x579`, never the live Horz value. `k = 0` when the snapshot is below Single 1.0 (`0x5757fc`), otherwise the FISTP integer of the snapshot (`0x403700`); `digits = 5 − k` for `k < 4`, else 2. Text = fixed decimal + `" Sec"` (`0x575808`); when `k > 9` and the text is shorter than nine characters, exactly two spaces (`0x575818`) are prepended once. Selector 0 draws at (10, 10) in 0xffff00, selector 1 at (300, 10) in 0xffffff. An invalid x draws nothing and erases nothing. No timer test.
- **M2 format** [S] (`0x486268 → 0x40cf28 → 0x40c5dc`, dispatch `0x40c6c0 → 0x40c778`): mode 2 fixed decimal, precision 18, no grouping. The decimal separator cell `0x5b880f`, the x87 control word and the FBSTP/carry path are not reproduced (WEB-MARK-NUMERIC).
- **M3 timer** [S] (`0x5750c8..0x5750e0`, `0x575520..0x57552f`, setter `0x448ff4`). MouseDown returns before any write while the main Timer1 runs; the line helper refuses independently; Move and Up have no timer test (the line refuses, the labels still run, a matching Up clears its flag). Receive resets the indices and enables the timer; Stop only sets the pending flag, so no new Down is admitted until the finish disables the timer. FormDblClick has no timer test.
- **M4 ownership** [S] (`0x5750c8..0x575469`). Code 0 sets `+0x586` and attempts the first mark locally: line, label(first, requested x), label(second, stored). Code 1 sets `+0x585` and attempts the second at the origin, then the main if the origin is a child, then the other present children in slot order 1, 2; every target uses its own snapshot and its own collision compare, and a refusal never stops a later target. This is a broadcast of attempts, not a shared stored coordinate. Move: `+0x586` with ssLeft (0x8) wins over `+0x585` with ssRight (0x10). Up: first with code 0 clears `+0x586` after its attempt; second with code 1 clears `+0x585` after the origin attempt and before the broadcast. Left/right follow the conventional VCL TMouseButton/TShiftState reading [I].
- **M5 limits and collision** [S/D] (`0x575510..0x57567e`, FormCreate `0x572630..0x57267f`). Positions start at −1; `lastBackupY = Display.Height − 1 = 141` (DFM 401 × 142). With `lastBackupY ≥ 0`, a requested x equal to the other mark's stored x returns before the store. No x ≤ N guard: negative x is stored and not drawn; x > N is stored. The y = 0 pixel restore that precedes the compare is not modelled. Int32 equality (−1 collides with an unset other mark, structural).
- **M6 Clear and Paint** [S] (`0x57546c..0x57550c`, Paint tail `0x572d63..0x572daa`). If the origin's second ≥ 0: second := −1 and Paint for the origin, then the main if the origin is a child, then every other present child (set and Painted whether or not it had a second). Otherwise, if the origin's first ≥ 0: first := −1 and Paint the origin. Otherwise nothing. Paint's tail calls the same line helper for first and second when ≥ 0, then label(first) and label(second). Each Paint is a full state transition (refresh: beam, `+0x583`, title and the title-change lastX reset).
- **Receive reset** [S] (`0x5746c8`/`0x5746d2`): the main and then each child get −1/−1 before that receiver's Paint. The captured block does not reset the native drag flags, so the port does not either.

The DFM binds FormDblClick to the **form's** OnDblClick; Display1 (TPaintBox) has no OnDblClick of its own. Canvas-to-form forwarding is not witnessed.

## Web policies (proposed in CONTRACTS.json, implemented here)

- **WEB-MARK-DOMAIN.** Fixed logical 401 × 142 canvas and N = 400; the Horz domain stays 0.5..16. Columns are integers 0..400. A press maps `floor((clientX − left) · 401 / cssWidth)` and is refused outside 0..400; a captured drag is clamped to 0..400. Y is never read. The line is drawn from y = 0 to 141 [I/W]: the native end is `Self+0x4c − 1` (a form field whose value is not established).
- **WEB-MARK-INPUT.** One First/Second selection per window (component state, default First; selecting places nothing). Primary mouse uses the selection, secondary mouse always the second; primary touch/pen with button 0 uses the selection; other buttons and secondary touches are ignored. One pointer lease for the whole bank holds pointerId, pointer type, button, origin window, mark code and the last delivered column; another pointer can neither steal it, move the mark nor end the gesture. The press focuses the display without scrolling and captures the pointer (a failed capture makes no attempt). A release is the matching pointerup or a pointermove reporting the lease button with its bit gone (chorded buttons). Moves follow the browser's event coalescing; skipped columns are not filled in, so a drag ending on a collision depends on sampling, as native mouse-move delivery does. Context-menu suppression and `touch-action: none` apply to the overlay only.
- **WEB-MARK-CANCEL.** pointercancel, lostpointercapture, Escape on the display, focus leaving the display, window blur, a hidden page, a foreign modal `<dialog>` (observed only while a lease exists), the route becoming inactive, a project operation, the cards becoming inert (antenna surface, date dialog, Pulsar Parameters, close box), Open/activate, Add, Close, Receive start, Clear and keyboard placement end the gesture. The drag flag is cleared with no attempt, the last accepted marks stay, no final coordinate or rollback is invented, and a later up of that pointer is ignored. These are web ownership rules, not native drag-flag cancellation. A lease and the main timer never coexist.
- **WEB-MARK-KEYBOARD.** A named position field (`role="spinbutton"`, `aria-valuemin` 0, `aria-valuemax` 400, `aria-valuenow` only when set) shows the stored column of the selected mark and is blank while unset. Enter or **Place** commits a draft of 1..3 digits with a value 0..400 (one MouseDown with the selected code, then the end of its flag: the same local/broadcast order, collision and timer gate as a press); an invalid draft is kept, marked invalid and announced, and no mark changes. Home/End place at 0/400. **Deviation from the proposal (approved):** ArrowUp/ArrowDown step a placed mark by one column from its stored value (unset or beyond 0..400: no attempt). A step onto the other mark's column collides like any placement and the stored column stays, so arrows cannot pass the other mark; the help says to type a column (R-RX3 review R1). No skip-over is added. ArrowLeft/ArrowRight keep their caret movement because the field is editable. Escape restores the stored value. Held keys act once. The field and Place are disabled while the timer runs ("available after the sweep finishes").
- **WEB-MARK-CLEAR.** A **Clear mark** button per window runs the recovered FormDblClick priority. Double-click with the primary button on the overlay runs the same command as a declared browser binding; the browser sequence pointerdown, pointerup, click, pointerdown, pointerup, click, dblclick first places the mark twice and then clears. This is not a native TPaintBox forwarding claim, and no VCL suppression or delay is invented.
- **WEB-MARK-RENDER.** Stored positions and the last drawn labels are kept separately and shown in a readout (`data-mark-*`, `data-label-*`), so a refused attempt whose label shows the requested time is visible next to the unchanged stored mark, per channel. Marks are drawn on an overlay canvas above the base display from a logical overlay composed from the mark events (Paint empties it; a stored line sets it; a label overwrites its own selector). The overlay has its own pen and stroke colour and is cleared and redrawn on every change, so it never contaminates the base canvas's next trace segment, including after a log truncation or a temporarily unavailable context. Drawing the overlay never runs Paint, a refresh or the random stream; Clear runs its recovered Paint transitions and each paint event carries the receiver as that stage drew it (`painted`), because a later Paint in the same Clear can change titles and every lastX. No GDI backup bytes, partial y = 0 restore, font, clipping or pixel parity. Colours follow the BGR TColor reading [I] (first 0xffff00 shows cyan, second white).
- **WEB-MARK-NUMERIC.** binary64; `roundNearestEven` only for the digit-selection integer k; `formatFixed` (Number.toFixed with a dot) for the text; the suffix and the conditional two-space prefix as recovered. The exhaustive check over H ∈ {0.5, 1, 2, 4, 8, 16} × x 0..400 shows every value terminates within its digit count, so there the text does not depend on a rounding rule; this validates the declared policy, not x87, FBSTP/carry or locale equality. H = 0.125 and 0.25 are formatter-only vectors, not UI scales.
- **WEB-MARK-LIFETIME.** Marks live in the monitor only: not in Save investigation, sessions, CSV, PLR, the notebook or storage. Close/reopen and Add start at −1 (FormCreate), Receive resets them, a project operation keeps them, reload resets everything. Each window labels with its own sweep snapshot (+0x579), not the live Horz: FormCreate sets it to 4 s, so a new window, or the main before its first Receive, labels at 4 s whatever Horz shows; a child's activation copies the main's live Horz but not the snapshot (0x5728dc); Receive start copies each present window's Horz into its snapshot. The scope text says so (R-RX3 review F1).

Focus moves only to the display on a pointer press. Status announcements: press, release, keyboard placement/step, Clear, the timer gate and the end of a gesture, with per-window collision outcomes; moves are not announced.

## Remaining gaps

Historical FPU control word, scaling helper `0x404984`, FBSTP/carry and the decimal separator (exact native text); GDI clipping, palette, font, TextOut opacity and the partial collision restore (pixel parity); the native line end `Self+0x4c − 1`; TPaintBox-to-form double-click forwarding and native event order; native drag-flag behaviour on capture loss. Record, Identify, PLR, Align, audio and automatic measurements remain outside R-RX3. The App touch test relies on the pinned Chromium accepting a selective `Input.dispatchTouchEvent` touchEnd list (the installed protocol comments say TouchEnd must have no points). A test-only guard confirms a non-primary pointerup with no primary pointerup before the first finger continues. This is not portable CDP, OS multitouch or native parity. Whether a real mobile double-tap fires dblclick on the overlay (placing twice, then clearing) is not checked on a device; the binding is unchanged (R-RX3 review H1).
