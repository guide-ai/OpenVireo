## Source sequence

`0x59c620..0x59c88d` checks the request success flag separately from finished, copies the supplied body and releases the request owner. Its parsing route repeatedly consumes LF-delimited lines until case-sensitive `Pos('END') == 1` or `Pos('#END') == 1`. These are **prefix matches**, not trimmed/exact line comparisons. Thus `ENDING` also satisfies the source marker predicate. The marker closes the preamble; it is not an end-of-data marker.

The immediately following line is passed to the header method at virtual+0x1c. Exactly the next line supplies the coordinate descriptor. The decimal branch requires both `hh.hhh` and `dd.ddd`; the source also has a sexagesimal alternative which is outside this implementation. Comments or blank lines between marker/header/units are not searched past to repair the sequence.

The checked virtual+0x10 dispatch reaches `0x59ced4..0x59cf57`. It consumes every remaining body line, skips only lines whose **first byte** is `#` and calls the candidate reader. A subsequent inspection of its insertion helper established that accepted candidates enter a **sorted RA/DEC list with cursor-dependent ties**, rather than preserving physical insertion order. The original framing-only description omitted that container behavior; it is corrected here and implemented separately in [source ordering and selection](CAMERA-NOMAD-SOURCE-LISTS.md). The immutable diagnostic ledger retains physical file order deliberately. Neither route deduplicates or stops on a subsequent body `END`. A body `#END` is a comment under this rule. The row reader's caught conversion failure and selected-magnitude rejection return false; the body loop continues. Web admission errors are retained as explicit invalid entries rather than silently erased, repaired or represented as an observation.

The complete line helper `0x48672c..0x4867fa` returns text before the first LF and removes that text plus the delimiter. When no LF remains it consumes the entire remainder. A trailing LF therefore does not fabricate a final empty row; two trailing LFs do retain one real blank body row. The native helper retains CR. **This bounded implementation admits printable ASCII and LF only and explicitly rejects CRLF, tabs, BOM and other encodings.** It does not claim full native encoding/locale parity or normalize a downloaded response.

## Ownership and scope

The parser copies the caller's byte buffer before reading, preserves the exact admitted ASCII text and physical line byte spans, and freezes its context and complete ledger. Outcomes are comment, candidate, selected-magnitude rejection or invalid with bounded row error code/field. Duplicate identifiers and invalid lines remain visible in their original order. An invalid structural header/descriptor fails atomically. Empty bodies are structurally admissible but carry no observing-success claim.

The 2MiB, 10000-line and 4096-byte-per-line limits are web admission bounds. Explicit band/epoch context and the row reader's finite Number/Single policy remain mandatory, including when no rows exist. No browser time, identity, catalog response, missing magnitude, selected field, seed or native metadata is supplied automatically.
