## Saving and closing have additional owners

The Save handlers write their saved flag from the actual save result; only success changes the status to Image Saved. Save wrapper`0x521c84` supplies the owned raw matrix and writer object to`0x522c28..0x5230db`. That complete dialog/writer path resolves configured names/directories, then calls the previously captured header writer and, only after header success, the plane writer. This narrows the output ownership chain; it does not supply missing observational metadata or prove original FITS interoperability from a synthetic frame.

CCD CloseQuery prompts about the unsaved image. IR CloseQuery additionally validates configured resource directories and can instantiate **TMountCDROM** before reaching its unsaved-image prompt. Its Regions/table path handling is not the CCD close flow. Closing also affects observatory controls and image-object ownership. A generic shared hide/cancel rule would omit these dependencies. Native mount/system dialogs remain outside the web port; their resource/configuration role must be resolved explicitly rather than executed or copied as a browser acquisition.
