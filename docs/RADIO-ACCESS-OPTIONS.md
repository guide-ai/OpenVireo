# Radio configuration and PulsarList1 availability (R-RX7)

R-RX7 ports who may change the radio options and when the original program's `File ▸ Pulsar List...` item (PulsarList1) is available. It is a bounded controller: the Preferences gate, the one ported option (Access Pulsar List), the Radio... child dialog's snapshot and result, the environment copy the radio panel reads, and the item's Enabled/Visible flags. R-RX8 delivers the item's command, PulsarList1Click, on this card as `File ▸ Pulsar List...` (WEB-ACC-LIST-01): it is rendered only while the latest Visible flag is set and enabled only while Enabled is set; its write and window activation are specified in [RADIO-PULSAR-PARAMETERS.md](RADIO-PULSAR-PARAMETERS.md) (WEB-PP-LIST-04). The flags remain the web history of the chosen scenarios, not a classroom configuration (G9).

- Core: `src/core/radioAccessOptions.ts` (pure, imports nothing). Tests: `src/core/radioAccessOptions.test.ts`.
- UI: `src/components/RadioAccessOptions.tsx` (`useRadioAccessHost`), mounted by `RadioTelescopeRoute.tsx`. App flows: `tests/radio-access-options-app.spec.ts`.
- R-RX8 command: pure preparation `src/core/radioPulsarListCommand.ts` (tests `src/core/radioPulsarListCommand.test.ts`), committed by `RadioTelescopeRoute.tsx`; App flows `tests/radio-pulsar-list-command-app.spec.ts`.
- Provenance: [RADIO-ACCESS-OPTIONS-PROVENANCE.json](RADIO-ACCESS-OPTIONS-PROVENANCE.json).
- R-RX9: the full Radio Simulation Options form under an explicit numeric authority, its projection and ownership rules are in [RADIO-SIMULATION-OPTIONS.md](RADIO-SIMULATION-OPTIONS.md). Everything below describes the startup state, where that authority is absent.
- Front T11a (2026-11-06): the form's Site... button and the radio site; see [Radio site (Front T11a)](#radio-site-front-t11a) below.

Tags: [S] static disassembly, [D] DFM resource decode, [I] inference, [W] web adaptation (not native behaviour). Tests are evidence of this implementation's contract, not an oracle for the original program. Nothing was executed or emulated.

## Web policies [W]

- **WEB-ACC-GATE-01 One gate (Front T1, 2026-11-06).** The card has no gate button of its own: it reads the page's instructor gate, which Instructor mode… in the page header opens (the web form of the Demonstration Mode branch's gate write, with no password and labelled as no lock; docs/OPTICAL-OPTIONS.md) and Leave closes. Demonstration Mode's other effects (`0x54c`, the `+0x80` call and `0x587dbc`'s menu writes) are not ported. No login, administrator, credential or classroom configuration is offered or read. Reloading the page closes it. Until T1 the card had its own "Apply the Demonstration Mode gate" scenario button.
- **WEB-ACC-FORM-01 Partial forms.** While the numeric authority is absent (startup; R-RX9 WEB-RSO-AUTH-01 replaces the child by the full form once the learner chooses a compiled branch): the parent shows only Radio..., OK and Cancel; the child only Access Pulsar List, OK and Cancel. Both say what is not ported. Web OK leaves every numeric value untouched; the original OK re-parses the numeric fields from their text (possible rounding, error box, dialog kept open), which is not ported. No settings file is loaded or written; OK's save confirmation is not ported and the status says so.
- **WEB-ACC-PRES-01 Presentation.** The USER OPTIONS! box and the dialogs are application-modal over every radio card, presented only on the active route outside a project operation and with no foreign native `<dialog>`; they yield, keeping their state, to an antenna surface or a pending receiver close box/Record dialog that arrives meanwhile (pending, not only presented: a Record dialog that became pending behind an antenna box keeps the configuration unpresented when that box closes, so the Record dialog takes focus alone; the configuration returns after it). The other radio cards stay behind an open configuration, presented or not; the control panel (and so an antenna box that took over) is behind it only while it is presented. Handler-time admission [W]: card actions (the close recipient and the compiled-branch opt-in) are refused while this card's own box or dialog exists; card and dialog actions are both refused while a surface with priority exists now (latest antenna state, receiver close box/Record dialog, date dialog, Pulsar Parameters) or a foreign native `<dialog>` is open. A refused action changes nothing and leaves the status unchanged; committed antenna/receiver events are not gated. Escape is Cancel (box: OK) and stops there (it never reaches the parent or the card); held Enter/Escape are ignored; Tab is trapped; Enter activates the focused button only. There is no X-close (its native outcome, possibly mrCancel without the restore, is not established).
- **WEB-ACC-FOCUS-01 Focus.** The opener → the parent's Radio... button → the checkbox; on close focus returns to Radio..., then to the opener, or to the card heading when the opener cannot take focus. A suppression (hidden route, project operation, foreign dialog, an arriving antenna or receiver surface) moves no focus; presented again, the surface takes focus the same way and keeps its state.
- **WEB-ACC-MENU-01 Readout.** The card shows the item's state (hidden; hidden with Enabled set; shown and enabled; shown and disabled), the raw flags, whether the first activation already happened, the last menu event and a plain note on the command (WEB-ACC-LIST-01; until R-RX8 it said "Command not delivered"). The first activation is the antenna's committed `activated` outcome (RA-04, the same guarded block); option edits, route hide/show and panel close/reopen do not re-run it. The interactive texts use plain labels; the native fields behind them are: Preferences gate = env+0x37d8; Access Pulsar List option = record+0x941 (RadiOptsObj); panel's copy = env+0x37d6 (in env+0x2e95); last Radio... result = env+0x37d9; the File ▸ Pulsar List... item = PulsarList1 (command PulsarList1Click, delivered by WEB-ACC-LIST-01); main form = TEnvironment1; radio panel = TRadioLab; close message = 0x53a; first-activation guard = TRadioLab+0x4d5.
- **WEB-ACC-LIST-01 File ▸ Pulsar List... (R-RX8).** Below the readout the card renders a button with the native caption (`Pulsar &List...` without its accelerator), distinct from the authored reference Open of Pulsar Parameters, which keeps its label and stays read-only. Presence and state come from the latest flags only: hidden (also hidden with Enabled set) renders no button; shown and disabled renders it disabled; shown and enabled renders it enabled. The current Access option, the catalog, the receivers and the antenna are not folded into the flags; they are separate web refusals at the click. The click calls the route's `runPulsarList`, which checks, on the latest refs and in the order of WEB-PP-LIST-04, the route (`inactive`), the flags again through `menuNow` (so a Receiver Open earlier in the same task already refuses with `menu-disabled`), the catalog, any open surface, the receiver session and its boxes and the pointing; a refusal changes nothing. An admitted click writes the receivers' shared source and activates Pulsar Parameters; it never writes the menu flags, calls `onReceiverOpened`, opens a receiver or moves the shared cursor afterwards. A polite status (`data-outcome` hit, miss or the refusal reason) names the shared source name written and, separately, the record the window shows (the first record whose J2000 name contains it, which can be an earlier prefix or duplicate match); a hit on a record with an empty J2000 name (`data-outcome` still hit, the name taken from the command's result, never from the seed) says instead that the record's data and B1950 name replaced the shared source and that, with no J2000 name to look for, the window shows the first record; a refusal says that nothing was changed. Focus moves to the Pulsar Parameters heading on success and stays on the button on a refusal. Held Enter does nothing more (`ignoreHeldKey`). The plain note describes the recovered search without addresses and does not promise a nearest-record search. Not saved; reload removes the command with the menu history.
- **WEB-ACC-HOOK-01 Receiver events.** The receiver workspace calls `onReceiverOpened` only after a committed Open whose picker ran (source hit or miss), also when reopening the existing main window, and `onMainCloseMessage` only after a committed main close whose events include `send-0x53a` (not for a refused close, the close box or the absence of receivers). Refused web guards run no native handler and call nothing. The receiver core, session, events, source buffer, cursor and Record logic are unchanged.
- **WEB-ACC-ROUTE-01 Close recipient.** Default: the main form TEnvironment1, the chosen scenario taken from the captured startup route (not an observed native delivery), which has no 0x53a handler, so nothing changes. "TRadioLab" is an explicit web adaptation applying the recovered handler; it never re-enables automatically and is not shown to happen in the original. DefaultHandler and window-procedure effects are not modelled.
- **WEB-ACC-SAVE-01 Session only.** Nothing is part of storage; reload resets the gate, values, last result, menu flags and recipient. Phase 1 item 1.5 saves the applied configuration in investigations; since Front T1 the gate field is always written closed (instructor mode is page-session state), and a Demonstration gate in a file written before T1 is read and not applied: the restored card follows the page's instructor gate.
