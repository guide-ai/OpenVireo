## Exact dependency

The source is VIREO `CLEA_VEO.exe`, SHA-256 `781bc9704b4674038267834a9ed21d502c455378d8fc9eb15a1653e20c52c54c`. This is a 32-bit Windows program; this proposal concerns that edition, not the user's historical Windows 3.1 installation.

The recovered path is:

1. `0x593f64` builds a 249×249 integer Gaussian table in BSS. `0x59422c` builds 15 brightness levels; `0x5942dc` applies the recovered cutoff and tone map. The new pure helpers implement table arithmetic with the documented Number/nearest-even adapter.
2. `0x594488` paints a native 249×249 bitmap and calls VCL `TCanvas.StretchDraw` (`0x42cb80`). The one-based painting loop touches coordinates 1..249; coordinate0 is initially black and coordinate249 is outside a 249-pixel bitmap. The helper arrays are table values, **not** a faithful raster of that bitmap.
3. Its TBitmap VMT at `0x42a984`, slot+0x14, points to `0x431714`. Bounded independent disassembly and REA byte evidence show GetDeviceCaps(BITSPIXEL)×GetDeviceCaps(PLANES), source-depth comparison, SetStretchBltMode(4) on the lower-color destination branch and mode3 on the nonmonochrome alternative. Native StretchBlt is called at `0x431927`; palette selection/realization surrounds the operation. The native body was absent from Ghidra's procedure inventory, so it is identified by VMT bytes, exact-address byte evidence and independent objdump, not a fabricated Ghidra function dossier.
4. `0x59456c` rotates the synthetic stamp with integer conversions; `0x594808` replaces a scene pixel only when the source red channel is nonzero and larger. Photographic galaxy images take the native bitmap-copy path `0x597470`. Stars are drawn after galaxies, then the larger sky image is cropped and instrument overlays are applied.
5. `0x53e338` reads 57 pixels from the final telescope image, sums R+G+B and divides by57 before integer conversion. Galaxy throughput is 1 at level>=200, otherwise (level/200)^2. Those pixels therefore affect the scientific source mean, not just appearance.

Microsoft documents [COLORONCOLOR pixel deletion versus HALFTONE block mapping](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-setstretchbltmode), and [StretchBlt destination-format conversion](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-stretchblt). These API descriptions do not provide an original CLEA session's display depth, palette, driver result, exact deleted-pixel alignment or x87 control word. A browser resizer would introduce a new contract. A Windows oracle can establish a **specified reference configuration**, not recover the user's unknown historical display.

A separate synthetic diagnostic uses the recovered level14 table, a 12×6 reduced stamp and the 3×19 slit. Two alternative point-deletion alignments produce channel sums1608 and1710, rounded levels28 and30, and throughputs0.0196 and0.0225 (absolute throughput difference0.0029; the second is14.7959% above the first, while the first is12.8889% below the second, for identical supplied amplitude). This is a deliberately unrotated synthetic2:1 stamp with a black background, not M82, NGC4889 or any measured target. It omits later rotation, stars and complete scene composition; its one-based paint offset is included in the diagnostic. Neither alignment is asserted to be GDI. This demonstrates sensitivity, not the actual error of either platform.
