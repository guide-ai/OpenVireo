# Silent receiver monitor R-RX2 (Radio route)

The Receiver button of the radio control panel opens a TRcvr_Form1 main receiver and up to two child channels as cards. Each card has the recovered controls and a logical 401 × 142 display. The display is drawn from the R-RX1 signal chain ([RADIO-RECEIVER-SIGNAL.md](RADIO-RECEIVER-SIGNAL.md)) with a learner-loaded reference catalog.

This is a **modelled display, not an observation**. It is silent and temporary (not in Save investigation; reload resets it). As first delivered, R-RX2 did not record and did not port Record, sound and volume, Identify/Properties, Align, PLR writing or the Add Current Item / PulsarList menu effects. Later increments added display marks (R-RX3, [RADIO-RECEIVER-MARKS.md](RADIO-RECEIVER-MARKS.md)), Record, Identify, the modal Properties and the Save question's No handoff to Pulsar Analysis (R-RX4, [RADIO-RECEIVER-RECORD.md](RADIO-RECEIVER-RECORD.md)), and Align, its layout and message 3 (R-RX5, [RADIO-RECEIVER-ALIGN.md](RADIO-RECEIVER-ALIGN.md)). Since R-RX6 the PulsarList menu effect is modelled as a session action but not delivered by the UI (its runtime availability is unproven), and the Pulsar Parameters Open only reads the shared buffer ([RADIO-PULSAR-PARAMETERS.md](RADIO-PULSAR-PARAMETERS.md)). Still not ported: sound and volume, saving a recording to a file (the native Save Yes, `0x56b36c`), window minimize/maximize states and AL-RESIZE, PLR writing and the Add Current Item menu effect. It does not complete Radio or any of the 58 capabilities. Native equivalence is not established: no CLEA execution, emulation or native trace was used, and tests are contract checks of this implementation.

Binary `CLEA_VEO.exe` SHA-256 `781bc9704b4674038267834a9ed21d502c455378d8fc9eb15a1653e20c52c54c`. Evidence tags: [S] static listing, [D] DFM/resource default, [I] analyst inference, [W] web policy. Paths, hashes and VAs are in [RADIO-RECEIVER-MONITOR-PROVENANCE.json](RADIO-RECEIVER-MONITOR-PROVENANCE.json).

## Ported contracts

- **RXD-01/02 trace store** [S] (`0x5720cc`, `0x572130`, `0x5721a8`, `0x5721c4`). K = Word(Display.Width) − 1 = 400; max index Word(K − 1) = 399; append only for x ≤ 399 (Word y, lastX := x); lookup beyond max gives 0. Reset zeroes 0..max and lastX and stores dt. The main store is reset inside the source refresh (`0x574c0c`) before the profile build; children are never reset. GetMem storage is not zeroed, so never-written child entries are `null` [W] and lift the pen when replayed.
- **RXD-03 Paint** [S] (`0x572a20`). Order: parameter refresh → teal background → grid (H-dependent step and minor count; majors 10 at H = 1, 5 below 1, Round(H) otherwise; ticks 111→120/130; final major at x = W) → yellow pen → replay of 0..lastX only when not receiving and lastX ≠ 0 → baseline `0x572dd0` → annotation → marks (always −1 in R-RX2; R-RX3 ports the tail, drawn on a separate overlay). Paint is a state transition (its refresh writes `+0x405`, `+0x583`, title and caption).
- **RXD-04 annotation** [S] (`0x572e24`). fixed1(H) + `" Sec "` at (10, 124); fixed2(f) + `" MHz "` padded with `" "` to ≥ 12 characters at (307, 124); colour 0xff00; font colour and PenPos restored. Writes no state and draws no science.
- **PARAM refresh** [S] (`0x572f8c`). Aperture text, the beam, `+0x583 := pointer && +0x405 > +0x51f` (strict, NaN false; correction F4: also written at Activate), titles. The main title changing while not receiving sets every lastX := 0. Labels: Freq fixed2, Step caption `0x5b4aab + 5i`, Vert fixed2, Horz fixed1, ModeDisp `Receive`/`Stop` (`+0x39c`, not the Mode button), AlignDisp (main; R-RX5: the stored caption `+0x3bc`, `Yes`/`No` from `0x5bce08`, see `docs/RADIO-RECEIVER-ALIGN.md`), RcrdDisp `Off`.
- **FORMAT-2 beam** [S] (`0x486f4c` with `0x486b20`). Decimal minutes with one decimal, 60-minute carry, whole degrees wrapped below 360, four-character head, `'0'` prefix when the pre-carry rounded minutes are below ten (quirk kept). Defaults (600 MHz, 100 m): `"   Aperture: 100 Meters    Beam (HPBW): 0 Deg 41.9'"`. Positive `+0x92c` gives the Effective FOV text instead.
- **Titles** [S/I]. Route branch with exercise byte `+0x383f` = 6 (RadioPulsars1Click `0x58ab9c`) and `+0x939` = 1 (compiled default `0x5a908a`): `"Pulsar " + legacy name` (ShortString[15]) when in source, else `"No Pulsar in Beam!"`. Children: `"Receiver n (Slave)"`. Other branches are not reachable on this route and not ported. Title and aperture text are `''` before the first parameter refresh as a web initial state [W]: the generic InitInstance zero-fill `0x404f1c` (`runtime-init-instance.asm`) is recovered, but the receiver form's creation path is not independently linked to it, so no native initial value is claimed.
- **FRAME** [S] (`frame-canonical.asm`). Position (main increments, child copies) → `+0x583` → main title rewrite on change (no lastX reset) → erase band (pos, 0)–(pos + 10, 111) → signal (which may run the coupling refresh, so the position is re-read) → Move or Line to (pos, row) → append → at pos = N with no pending stop, erase (0, 0)–(10, 111) and MoveTo(0, row) → finish or reset. The finish enables the main's own Add (idle helper `0x575a38`).
- **MODE** [S] (`receive-mode-canonical.asm`). Start: Add off, `+0x42d := 0`, Paint, snapshot, source refresh, stamp, timer on, refresh; each child copies and Paints. Stop: `+0x42d := 1` and the refresh.
- **FREQ** [S] (`frequency-down/up.asm`). Candidate f ∓ step; down below 400 → 400, up above 1400 → 1400 (Singles `0x5742ec`/`0x57446c`). An unchanged candidate only beeps (no refresh). Allowed while receiving; then the annotation is redrawn.
- **INCR** [S] (`step-*-canonical.asm`). Index 1..5, beep at a limit, step 10^(i − 3) (WEB-RX-NUM-01), refresh.
- **ADD** [S] (`add-channel-canonical.asm`). First empty slot; slot 2 disables the main's Add. Correction: no empty slot creates nothing (`0x574ead..0x574eaf`); this is reachable after a finish re-enables Add with both slots used.
- **CLOSE** [S] (`receiver-close.asm`, `0x5726f0`). Main: children closed 2 then 1, `0x53a` sent by direct virtual dispatch to `Application+0x44` (`0x40516c`), recorded as `send-0x53a` (was `post-0x53a`). Child: slot cleared and the main's Add enabled. The close query box text and caption (`0x572878`/`0x5728c4`, flags 0x40) are shown.

## Web policies

- **WEB-RX-AUDIO-01 (silent).** Every receiver has `+0x42f` = false by web restriction; the compiled default `+0x93f` = 1 and FormCreate's `waveOutGetNumDevs` call are not reproduced. Under SILENT-01 (fresh 140-byte zeroed `PulsarSoundObj`, `+0x42f` false throughout; `AUDIO-OWNER-CLOSE-RESULTS.json`) the audio flags and fields stay zero and no receiver or science field changes. Natively the cleanup still calls `waveOutClose(0)` at every close and finish, and the constructor Randomize `0x576712` runs at unit init; their OS effect is unobserved. **This is not a native no-op claim.** Audio stays excluded until anomaly PRE-01 (`+0x51`/ESI in `0x576c28`/`0x576b04`) has an evidenced contract; it is neither corrected nor reproduced, and nothing is routed through `0x57724c`/`0x576c28`/`0x576b04`.
- **WEB-RX-CAT-01.** A learner-loaded reference catalog is required (native: Pulsars.dat read at TRadioLab FormCreate). Load is refused while any receiver exists; Open is refused while a read is pending.
- **WEB-RX-TIME-01.** `now` = route `performance.now()` / 86 400 000, a monotonic day scalar (explicit deviation from Time `0x40d448`): no midnight or backward stall. JD always comes from the radio clock scenario, read without side effects.
- **WEB-RX-CAD-01.** One 40 ms browser interval (NT-branch reading of `0x48c394`; no host OS claim) while the main timer is enabled and no project operation runs. One batch per admitted tick, no catch-up; it keeps running on a hidden route and under modals. H is simulated seconds per sweep, not real time.
- **WEB-RX-SEED-01.** The k-th Randomize site of the route session uses `(base + k) >>> 0`; base defaults to 1, is editable only while no receiver exists and is not saved. Seeded sites: `0x572376` (FormCreate) and `0x562ba0` (first allocation). `0x576712` is not represented (in every ported path `0x572376` reseeds first); the audio `Random` sites `0x5770b9`/`0x5770db`/`0x5771c1` are unreachable under SILENT-01. No QPC/GetTickCount claim.
- **WEB-RX-ERR-01.** A Receive refusal is atomic (no Paint, trace reset or stamp); native rollback is not established. A tick refusal keeps the bank, retries every 40 ms and shows one persistent alert: the native outcome is not established; Stop is accepted but stays pending while the error persists; closing the main window recovers. A reassociation miss or a restored name may also clear it [I]. A gated or disabled tick keeps the error; only a successful delivery or closing the main window clears it.
- **WEB-RX-ACT-01.** Activation (Show → FormActivate [I]) runs at Open, at every Receiver press and at Add. It is not idempotent natively (title/lastX reset, child copies); focus moves between cards are not activations.
- **WEB-RX-PAINT-01/02.** Paint runs at canvas mount (first WM_PAINT after Show [I]) and at Receive start [S]. The bitmap is retained; there are no expose or resize repaints. Each window keeps a bounded op log (4096 ops); when unseen ops were dropped, the canvas is redrawn purely from the state without a state transition, and the canvas pen is then set to the log's pen (from which the session chose the following Move/Line ops). Mount callbacks are stable: re-renders do not repaint or draw random numbers.
- **WEB-RX-GEOM-01.** Logical canvas 401 × 142 scaled by CSS; N = 400 fixed. Resize propagation, window states, pixel positions and border icons (Word mask 4 at `0x57268c`) are not modelled. R-RX5 ports Align `0x5bce08`, the guard `0x5bce09` and the layout `0x574fa4` as a card order (`docs/RADIO-RECEIVER-ALIGN.md`); AL-RESIZE `0x575080` stays unported. The baseline end 640 is the inferred logical pen extent (`Self+0x48` read as the form width, FormCreate passes 0x280 to `0x45d60c`), not a proven VCL/GDI identity.
- **WEB-RX-DISP-01.** Op order and coordinates follow the listings; replay uses zero-extended Words. TColor values are shown under the BGR convention [I]. No pixel, font, clipping or colour parity. The native Enter/Exit colour setters (7 pairs) notify and may repaint; they and the idle/receiving label colours are not reproduced. Focus and paint follow explicit web policy only.
- **WEB-RX-FOCUS-01.** Open → main heading; Add → new child heading; main closed → Receiver button (else the setup heading); child closed → main Add if enabled (else main heading); close box dismissed → slot-1 Close; Receive start keeps focus on Mode; the sweep finish moves none (the native form SetFocus is not reproduced). No hidden native owner restoration.
- **WEB-RX-KEY-01.** Held Enter/Escape is ignored on every receiver button (native spin auto-repeat not reproduced); no document key listeners. The Receiver button is outside the RA-19 key scope.
- **WEB-RX-CLK-01.** After each completed RA-13 tick of the antenna (also one chained by a manual E/W release) the receivers reassociate with limit 5, the latest catalog and that tick's pointing.
- **WEB-RX-OWNER-01.** No `0x53a` effect (the runtime `Application+0x44` value and OS forwarding are not observed; startup binds it to `TEnvironment1`, which has no 0x53a handler [S]). Open's unconditional `+0x480 := True` is not reproduced. Its conditional `+0x46c := False` is PulsarList1.Enabled := False when env+0x37d6 ≠ 0 (`0x567a6e..0x567a76`); it is not reproduced either, and the env+0x37d6 value and any re-enable stay open (G9; [RADIO-PULSAR-PARAMETERS.md](RADIO-PULSAR-PARAMETERS.md), "PulsarList1 availability [D/S]"). R-RX7 ([RADIO-ACCESS-OPTIONS.md](RADIO-ACCESS-OPTIONS.md)) adds, outside the receiver core and session: after a committed Open whose picker ran, the workspace calls `onReceiverOpened`, and the Radio configuration controller applies that conditional disable to its PulsarList1 readout; after a committed main close with `send-0x53a`, it calls `onMainCloseMessage`, and the controller leaves the readout unchanged for the default recipient TEnvironment1 or applies the `0x567af8` handler only for the explicitly chosen [W] TRadioLab recipient. The receiver core, session, events, cursor and Record logic are unchanged.
- **WEB-RX-ADD-01.** The accepted Add-while-timer refusal stays, although natively a child close re-enables Add during Receive.
- **WEB-RX-PP-01.** Superseded by R-RX6 ([RADIO-PULSAR-PARAMETERS.md](RADIO-PULSAR-PARAMETERS.md), WEB-PP-LIST-01..03, WEB-PP-CUR-01): the Pulsar Parameters Open reads the session's shared buffer (`sourceBuffer`) and is refused under the close box and the Record dialogs through the read-only gate (`boxRefusal`, `receiverBoxRefusal`); it writes nothing, so no receiver field, formula, seed, lease or card changes. Each committed Receiver Open or clock reassociation whose picker ran reports its catalog and pointing (`onSourcePicker`) so the window's shared list cursor follows. The modelled `overwriteReceiverSourceBuffer` has no UI caller.
- **WEB-RX-NUM-01.** binary64, round half to even (control word 0x1332 policy), `formatFixed`. Step values are exact binary64 {0.01, 0.1, 1, 10, 100}; `0x4270c0` is not identified and its Extended result is not claimed; 0.01 accumulation drifts in binary64. No x87 parity.
- **WEB-RX-OPT-01.** Compiled options only; `+0x939` = 1; exercise byte 6.
- **WEB-RX-PERSIST-01.** Nothing enters investigation JSON, CSV, PLR, the notebook, undo, the hot list or storage. Reload resets receivers, seed and catalog.

## Review resolution (2026-10-24, R-RX2)

Sources: `ROOT/analysis/radio-rx2-monitor-20261024-review/review.txt` (raw report) and the coordinator's `REVIEW-FINDINGS-VERIFIED.json` (2026-10-24T15:10:11.950359+00:00) under `/tmp/clea-static-research/radio-rx2-monitor-validation-20261024/`.

- **U1 (conditional renderer defect).** After the dropped-log repaint the canvas pen stayed at the repaint's end (640, 111) while the session had chosen the next Move/Line ops from `log.pen`. The renderer now sets its pen to `log.pen` after the repaint; trace, science state, RNG, timing and the Paint contract are unchanged. Scope: a retained single 2880 ms fake-clock jump did not reach the fallback (`U1-BEFORE`); one demonstrated trigger is test-only Canvas API fault injection (a temporarily unavailable 2D context, `U1-FAULT-BEFORE`). That is not claimed to be the only trigger, and no normal-use or native reproduction is claimed. The App regression reaches the fallback with the same injection and compares the next segments with an unfaulted seeded control run.
- **S1.** Gated or disabled ticks now keep a stored tick error, with the session unchanged; reproduced and tested with constructed caller states (non-increasing `now`, timer forced off) that the monotonic UI does not reach.
- **S2–S4.** Wording only: the seed help names the modelled reseed sites, the InitInstance zero-fill `0x404f1c` is cited as generic with its receiver-creation link not closed, and the R-RX1 scope sentence names the core module.
- **Not done:** the review's other suggested tests (annotation on a channel window's own canvas, a component-level re-render check) and the optional op-log ring buffer.
