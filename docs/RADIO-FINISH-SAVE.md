# Save from the finish question (R-RX17, Radio only)

When a receiver capture finishes, the recovered dialogs run in order: the full box, Identify, the modal Properties and the Save question (flags 0x23, "("No" -> Open Analysis Window)"). Until R-RX16, **Yes** in that question was disabled. R-RX17 enables it as a **web Save owned by the Radio route**:

- **Yes** opens a Radio Save dialog for the capture just committed. Yes itself chooses and writes nothing, and the capture lease stays held.
- **Choose file and save…** is a separate click. It runs the R-RX15 verified Save (the browser picker, write, close and an exact, bounded, fresh read-back), with a separate owner-aware receipt step.
- Only a verified copy ends the finish. The session then releases its own capture lease exactly once. The route stays Radio, Pulsar Analysis is not opened, nothing is erased and no new capture is armed.
- Every other outcome stays in the dialog with an alert: cancel, refusal, wrong extension, write, close or read-back failure, mismatch, stale data, or an abandoned attempt. **Back to the finish question** (or Escape) returns to the question with the lease still held; its **No** (release, then the analysis opens) and **Cancel** (release) are the R-RX4 answers.

The data is a **model-generated capture of the receiver simulation, not observed CLEA data**. The analysis Load question's Yes (E9) stays **gated**. Radio is not complete. No native Save dialog, wrapper, exception, window-effect or durability equivalence is claimed.

No CLEA execution, emulation, native dialog or native trace was used. The tests check this implementation's web contract, not the original's behaviour.

Binary `CLEA_VEO.exe` SHA-256 `781bc9704b4674038267834a9ed21d502c455378d8fc9eb15a1653e20c52c54c`; accepted base `f3575114d9d607a21f866bb060868f1620c20734`. Tags: [S] static listing (bounded GNU objdump copies reused from R-RX15/R-RX16), [I] analyst inference, [W] web policy. Listings, hashes and contract ids are in [RADIO-FINISH-SAVE-PROVENANCE.json](RADIO-FINISH-SAVE-PROVENANCE.json).

## Recovered facts (static)

- **E4-YES** [S] `frame-verified.asm` (SHA-256 `d31088cb…9ea4`):
  - `0x573d3f` calls the message box `0x47e09c`; `0x573d44` stores the answer at `[ebp-0x1c]`.
  - `0x573d47` compares it with 6 (Yes). `0x573d4d..0x573d54`: EAX = the analysis form `[0x5b5d84]`, then `call 0x56b36c` (the Save wrapper).
  - `0x573d59` jumps to `0x573d6f`, which only compares the original answer with 7. **The normal return of the wrapper is followed by no saved-flag or success test.** Yes also skips the main+0x468 enable (`0x573d5b..0x573d6a`) and the No branch.
  - The prologue installs its exception handler at `0x5737ae..0x5737b7` (`0x5737af push 0x573dc0`, then the prior FS frame and `FS:[0] := ESP`). At normal cleanup, `0x573d9f` unlinks the frame and `0x573da2 push 0x573dc7` supplies the return address for `0x573da7..0x573dbf`; that push does not install a handler. The handler entry is `0x573dc0 jmp 0x4056e4`. The continuation after an exception raised inside the wrapper is **not established**.
- **E4-NO-CANCEL** [S] same listing: any answer other than Yes enables main+0x468 through `0x4548ac` (`0x573d5b..0x573d6a`); No (7) calls `0x47a010` and then `0x476f40` on the analysis form (`0x573d75..0x573d8a`). These window effects stay unbound (B4 of [RADIO-RECEIVER-RECORD.md](RADIO-RECEIVER-RECORD.md)); the web No and Cancel are unchanged.
- **WRAPPER-CANCEL** [S] `writer-caller-56b36c.asm` (`b56926da…40f5be`), `0x56b550..0x56b678`: a dialog Execute that returns false reaches `0x56b5f2` (done := 1) and the normal cleanup; at the extension warning, Cancel (2) sets done := 1, Yes (6) loops back to the dialog and No (7) calls the writer `0x56a518`. The wrapper's exception frame goes to `0x4056e4`; a thrown-error continuation is not established. **A cancelled dialog returns normally.**
- **WRITTEN-AFTER-CLOSE** [S] `signal-write.asm` (`55069a74…bef7d`), `0x56a838..0x56a85d`: close `0x403bc8` and the I/O check `0x4030f8` precede `+0x97 := 1` and the `+0x9a` name copy; there is no `+0x96` store. The same receipt semantics as R-RX15; no durability is proved.

**Native vs web.** Natively, after a **normal return** of the wrapper (including a cancelled dialog) the frame ends the finish, whatever the wrapper did; the continuation after a **thrown** I/O error is unknown. The web is **stricter by explicit policy**: only a verified receipt ends the finish, and a cancel, refusal or I/O failure keeps the learner in the Finish-owned Save dialog. This is not a native continuation, and no native success confirmation or error path is invented.

## Web policy

- **WEB-RX17-01 Yes** [W]. At the finish question, Yes is enabled where the browser offers the save file picker (otherwise disabled with the `insecure-context` / `no-api` reason; No and Cancel stay). Pressed, it opens the finish Save dialog only when the session holds the capture's lease (`leaseId = captureId`), the capture is committed, and the document still holds that committed lease with this capture as its memory data. Otherwise nothing changes (`record-input`) and the question stays. Yes does no I/O, calls no picker and sends no host request. The web default stays Cancel (the native default is Yes).
- **WEB-RX17-02 Lease object** [W]. The dialog keeps the exact committed lease **object** that was current when it opened. Begin and the verified exit require that same object (identity, not an equal value or the same numeric id). A later lease that reuses the id, a re-committed lease, or a hand-made `{id, phase:'committed'}` is never admitted, claimed, recorded under or released by an old receipt. The context is kept through every notice and settlement step (`stepFinishSave` replaces only the sub-state).
- **WEB-RX17-03 Claim domains** [W]. `pulsarFinishWriteClaim` issues a claim only for the document's own frozen committed lease and its capture, bound to that lease object and to the data object, generation, metadata snapshot and samples (as a generic claim). `recordPulsarFinishWrittenCopy` refuses, in order: `claim` (not a finish claim, or the shared output claim is not exactly `('radio', token)`); `capture-lease` (bound to another lease object than the owner's, the lease is no longer the document's committed lease, or the capture is not that lease's); then `superseded`, `source-mutated` (`Object.is`, so −0 ≠ +0), `readback-size`, `readback-bytes`, `file-name`. A finish claim is refused by the generic recorder (`claim`) and a generic claim by the finish recorder (`claim`). The generic recorder still refuses any lease. On success only `written` changes; the lease, data, generation, analysis activity and output claim stay.
- **WEB-RX17-04 Verified exit** [W]. In the same task as the receipt, and only while the attempt is live, the session leaves the dialog with `verified` if this session still holds the lease (`leaseId = captureId = the dialog's lease id`) and `radioFinishSaveVerified` finds the document's current receipt for the dialog's lease object (still committed), data object and generation, with the reported name and byte count. The only host request is `release` of the session's own lease id, once. A repeated exit, an exit without a receipt, or an exit under a substituted lease is refused with no host request. The receipt is historical: a check at that moment, not file monitoring. Pulsar Analysis is not opened; the status says so.
- **WEB-RX17-05 Readiness and no deadlock** [W]. Choose is ready while the dialog's lease is held, no analysis read is pending and no output claim of either owner exists. An open analysis dialog (`analysis.modal`) is deliberately **not** a condition (WEB-RX16-06 reasoning). The R-RX16 arming Save, the Analysis Save and the Analysis Download keep refusing under the held lease.
- **WEB-RX17-06 Back, No, Cancel** [W]. Back (also Escape) is refused while an attempt holds the output claim (also an abandoned one, until it settled); otherwise it returns to the finish question with the same capture and the lease held. At the question, No releases once and opens the analysis (Load enabled), and Cancel releases once (R-RX4, unchanged). While the dialog is open, No and Cancel are refused.
- **WEB-RX17-07 Choose** [W]. Its own click, synchronous up to `showSaveFilePicker`: the guards (`detail > 1`, support, shown route, no project operation, presented, no foreign modal, mounted, no running attempt), then `radioFinishSaveBegin`, the shared claim `('radio', token)`, then the picker, with no await before it. A synchronous picker failure releases the claim at once.
- **WEB-RX17-08 Liveness and abandonment** [W]. Each attempt has a token; it is live only while the token is current, the workspace is mounted, the Radio route is shown and no project operation runs. A foreign modal does not stop it. A hidden route or a project operation makes the attempt dead before paint (epoch bump, `abandoned`), and it is never resumed when the route returns. A dead continuation aborts an open stream, records nothing, and releases the output claim only after that cleanup settled; the capture lease stays held. An unmount makes the attempt dead the same way; the existing disposal releases the session's own lease by id.
- **WEB-RX17-09 One Radio Save at a time** [W]. The arming Save prompt and the finish Save dialog never coexist in the session; there is one running attempt (`saveRun`) and one shared output claim.
- **WEB-RX17-10 Focus and layout** [W]. Entering the dialog focuses Back; Back focuses Cancel at the question; the verified exit focuses Record. A verified exit under a foreign modal takes no focus while a modal is open; it focuses Record once, after the last modal closes, only if no route hide, project operation, newer admitted action or focus request, or unmount happened in between. Later dialogs never refocus it: the one-shot intent observes modals only while it is pending, and the generic focus request rule (dropped under a modal) is unchanged. At that one opportunity it also refuses to move focus if another Radio surface covers the cards or a Record dialog is open; the intent is then consumed. Held Enter and Escape repeats are ignored, so a held Escape from the dialog does not continue into the question's Cancel. Every text that can hold a name wraps anywhere, including the card status that shows the verified file name (`.radio-receiver-card .radio-control-status`, no truncation or hiding); the dialog and that status fit at 1440, 375 and 320 px.

## Lifecycle

| From | Event | Result | Host |
|---|---|---|---|
| question | Yes (support ok, admitted) | dialog, no attempt | none; lease kept |
| question | No / Cancel / Escape | unchanged R-RX4 | release (+ open-analysis for No) |
| dialog idle | Back / Escape | question | none; lease kept |
| dialog idle | Choose | attempt = token (picking) | none |
| dialog pending | Back / Choose / Escape / No / Cancel | refused (inert) | none |
| pending, live | non-verified result | alert, settled, stays | none |
| pending, live | verified receipt | finish ends, stays on Radio | release (own id, once) |
| pending | route hidden / project operation | abandoned for good | none; output claim held until settled; lease kept |
| any | unmount | existing disposal releases the own lease by id; the dead attempt records nothing | — |

## Gaps and limits

| # | Limit | Effect |
|---|---|---|
| L1 | The native wrapper `0x56b36c` (dialog, naming, collision probe, remembered folder, its empty-list box and the extension warning's "No writes" path) is not ported | The browser chooses one file; the R-RX15 web rules apply. |
| L2 | The thrown-error continuation (wrapper and frame handlers to `0x4056e4`) is not established | Failures stay in the dialog; no native error path is claimed. |
| L3 | Web continuation is stricter than the native normal return | A cancelled or failed attempt keeps the learner in the dialog instead of ending the finish. Declared adaptation. |
| L4 | A browser stage that never settles (most plainly a picker promise) | The dialog (Choose, Back, Escape inert), the output claim, the capture lease and Analysis Load stay blocked until that provider promise settles. A route hide or a project operation marks the attempt abandoned but releases nothing early; no timeout or forced release (extends R-RX16 L4). The output claim and the capture lease stay independent. |
| L5 | Unmount teardown | Not runtime-witnessed: the App never unmounts the workspace. Only the pure ownership rule is tested (a late recorder call after the lease is gone records nothing). No mounted teardown witness exists. |
| L6 | main+0x468 and `0x476f40` window effects; that Yes skips `0x468` | Not ported (B4). |
| L7 | Physical durability, OS dialog behaviour, x87, FPU, RNG, GDI, locale | Not claimed; the receipt is historical. |
| L8 | Focus defaults (Cancel at the question; native default Yes) | Declared web choice. |
| L9 | `radioReceiver.record.yesGated` / `webDefault` in en.json are no longer read by the finish question | Left unchanged; an i18n completeness check, if one exists, may report them as unused. |
| L10 | Cancelling the deferred Record focus by a newer workspace action while the page is behind a foreign modal | Not reachable in the browser (the page is inert under the modal), so that cancellation is checked by review only. The route-hide, stacked-modal and later-dialog cases have App regressions; project-operation and unmount cancellation are review-only too. Native window effects and native activation order stay unclaimed. |
