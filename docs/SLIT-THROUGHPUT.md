# Bounded original object throughput

`nativeObjectSlitFraction` ports the defined branches of VIREO 0x50f338..0x50f467, SHA-256 `781bc9704b4674038267834a9ed21d502c455378d8fc9eb15a1653e20c52c54c`. Bindings and exact Extended constants are in `data/hubble/slit-throughput-provenance.json`. Existing REA evidence `ev_6e7bb16660d9d81879e2c4cc5dbab41d65b476b665a6095d99fbe51814be6bfd` covers the 304-byte body. Its abbreviated C pseudocode omits the FPU return branches; full assembly and independent bounded objdump are the evidence used here.

The object pointer being absent returnszero before reading image/type/coordinates. For a present object, decoded dispatch0x50f3c1..0x50f3cc sends types0/2/3 to the stellar branch and type1 to the galaxy branch. Other present types jump to a local return whose scratch value was not initialized in this path; the adapter rejects them. It does not invent a sky/type4 result or generalize all CLEA instruments.

Stellar 0x50f3d2..0x50f42a compares absolute raw objectRA−pointingRA toExtended 0.00028 hours, then absoluteDec difference toExtended 0.0064 degrees, both strictly less. Object coordinates are Double at +0x19/+0x21; pointing comes from observatory Extended +0x65f/+0x669. RA is not wrapped through zero, multiplied by 15 or corrected by cos(Dec) here. After both cuts the measured pixel level must be positive; result is 1, otherwise 0. Thus a positive-level galaxy transfer function is not a replacement for stellar throughput. Type 1 preserves the existinglevel >= 200 → 1, else (level / 200)^2 branch.

The supplied pixel level must come from a valid actual native image's recovered 3×19 sampling, not a library PNG, source-profile curve or fabricated pixel. The API validates integer 0..765. Caller supplies actual selection/type/presence and native coordinates; no default telescope, scene or pointing is inferred. Finite RA 0..24 / Dec −90..90 are explicit adapter support limits.

Coordinates and constants useNumber projections; no original x87/control word equivalence is claimed. For each stellar comparison, abs(abs(object−pointing)−limit)<=8*EPSILON*max(1,abs(object),abs(pointing)) raises`precision-required`. This conservative new support guard is not a measured error bound or a recovered physical margin. In particular, projected equality is not silently classified using a rounded Extended constant. Other finite supported cases use strict Number comparison; original exceptionalFPU/NaN behavior is not ported.

Independent Fraction vectors compare 30 synthetic Double-coordinate cases against the exact Extended constants, including all three stellar types, low positive/zero pixel levels, both angular cuts, negative offsets, unwrapped RA zero crossing and high declination. Six exact rational galaxy-level cases and two guarded boundaries are separate. A composition test uses the earlier independent 314-level fixture: cached configuration level 9 → prepared profile → paint → 57 pixels → throughput → explicit synthetic amplitudes. It does not create an exposure or observation.

The new catalog merge/index reports were reviewed: three callers re-resolve an old positional index after deletion; a fourth uses the retained pointer. They establish a conditional static divergence, not an observed full-session result. This helper neither changes that behavior nor attests that a supplied object was selected correctly. Source reports and hashes are retained in the provenance. Complete catalog ordering/merges/list context, actual native raster/transforms/throughput calibration and lifecycle integration remain separate gates. Original activation can choose sky mode after zero throughput; that state transition and its RNG consequences are not added by this helper. Acquisition stays disabled. No blocked Claude/security review or extension permission was retried.
