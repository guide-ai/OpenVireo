## Correction to the framing-only description

The body loop calls `0x492728`, which was previously described as a physical-order append. Inspection of the **complete helper and its actual virtual comparator** established sorted insertion instead. Constructor `0x59bed8` passes the list VMT through pointer `0x594e3c → 0x594e48`; method+4 is comparator `0x59be88`. That comparator uses RA first and DEC second. The earlier native-order assertion is corrected in framing documentation/provenance; the immutable physical-line ledger remains useful as an explicitly web diagnostic record.

`src/core/nativeNomadOrder.ts` ports the structured cursor/list insertion. The source helper searches forwards or backwards from the insertion cursor, then inserts at the head or after the located node and retains the new node as cursor. Resulting coordinates ascend under the declared finite Number comparison policy. **Equal-coordinate payloads are retained and their order depends on cursor history**; stable JS sorting, identifier sorting, deduplication or a fixed reversal would alter it. Four same-coordinate inputs A/B/C/D produce A/D/C/B; after a lower-coordinate Z, same-coordinate A/B/C produce Z/C/B/A. A different prior cursor can change these equal-coordinate placements.

Selection `0x59cc88..0x59cea9` rewinds the ordered catalog, applies virtual+0x14 (the recovered RA/DEC/magnitude predicate), and inserts admitted records into a **second** list with the same comparator/insertion contract. This second insertion can reorder equal-coordinate records again. The diagnostic ledger, catalog list and selected list are therefore separate views, all retaining original entry/line identity. Actual projection and random draw sequencing must use the admitted source list only after the other observing authorities are recovered; this module does not supply those authorities.

## Magnitudes and ownership

Selection initializes Single minimum25 and maximum−2 and changes them only for strict comparisons on accepted rows. An accepted magnitude27 leaves minimum25; an accepted magnitude−5 leaves maximum−2. Empty selection retains25/−2 and returns `hasSources=false`. These are native working sentinels rather than a replacement with mathematical infinities or a claim of measured image statistics.

Only the actual immutable object returned by this parser can enter the source-list stage. JSON reconstruction or a relabelled object spread rejects. Bounds are explicit, copied/frozen and checked even for an empty body; selected magnitude limit must already be a finite Single. This private object-ownership guard is a web safeguard. It does **not** authenticate service identity, response bytes/hash against a request, options, field/time or cache reuse. Accepted candidates retain the bounded row reader's Number/Single policy; native Extended comparisons, ties lost through Number conversion, malformed native exceptions and live cache behavior remain outside parity claims.
