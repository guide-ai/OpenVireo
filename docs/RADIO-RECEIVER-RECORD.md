# Receiver Record → Identify → Properties → No → manual Pulsar Analysis (R-RX4)

The main receiver window's Record button arms the recording byte. The next Receive records the receiver signals until the sweep after Stop finishes. The finish runs the recovered dialogs in order: the full box, Identify, the modal Properties and the Save question. **No** opens the existing manual Pulsar Analysis on that data. **Yes** (save) stays unavailable, with its reason shown. R-RX15 adds a separate verified Save in Pulsar Analysis ([PULSAR-SAVE-VERIFIED.md](PULSAR-SAVE-VERIFIED.md)); the three original Save-Yes paths (this question, the arming unsaved prompt and the analysis Load prompt) stay gated and only point to it. After a verified copy of the current capture, `+0x97` counts as set for E1 and E9: arming skips the unsaved prompt (the erase prompt is unchanged) and Load asks nothing. Any dataset change (erase, commit, import) drops that status.

This is a **model-generated capture of the receiver simulation, not observed CLEA data**. It is held only in this tab as the App's current pulsar dataset. It is not in Save investigation, CSV, the notebook or storage, and a reload discards it. Native equivalence is not established: no CLEA execution, emulation or native trace was used, and the tests check this implementation's contracts. No acceptance count changes.

Binary `CLEA_VEO.exe` SHA-256 `781bc9704b4674038267834a9ed21d502c455378d8fc9eb15a1653e20c52c54c`. Tags: [S] static listing, [D] DFM/resource default, [I] analyst inference, [W] web policy. Listing paths, hashes and VAs are in [RADIO-RECEIVER-RECORD-PROVENANCE.json](RADIO-RECEIVER-RECORD-PROVENANCE.json).

## Contracts

- **E1 Arming** [S] `0x57581c..0x57594c`. Record xors `0x5bce28`. When it became 1, the data list is not empty and `+0x97` is 0: MessageBeep, the unsaved prompt (`0x575958`/`0x5759dc`, flags 0x13). Cancel (2) clears the byte and skips the refresh. Yes (6) calls `0x56b36c`. No (7) falls through. The second check is not guarded by the byte: while the list is not empty, the erase prompt (`0x575a08`/`0x5759f8`, flags 0x41). OK (1) runs the clear `0x56a8e0`; anything else clears the byte. When the byte is still set, the three scratch Doubles := 0.0. Then the refresh `0x572f8c` writes RcrdDisp `On`/`Off` (`0x573668`/`0x573674`).
- **E2 FormCreate disarm** [S] `0x572622`: the byte := 0 for a new main and for Add of a child. RcrdDisp keeps its old text until the next refresh of the main.
- **E3 Receive header** [S] `0x574766..0x574969`, after the source refresh. Name: pointer `+0x4a2` set, exercise byte 6 (≠ 1) and `+0x939` = 1, so ShortString[40] of the buffer's `+0xd` (the catalog legacy name); no pointer: `''`. Aperture Word `+0x916`. Highest: contiguous children from slot 1. Frequency `+0x529` and gain `+0x53d × +0x40f` for the main and each present child; absent receivers' cells are not written. Start: profile owner `+0x12`. Interval: main `+0x419` (H/N). Then `+0x99` := 1, `+0x96` := 0, `+0x97` := 0.
- **E4 Frame store and finish** [S] `0x573a30..0x573a4a`: while the byte is set, the signal before display gain is stored as Double at `0x5bce10 + 8·index`. `0x573bbd..0x573d8f`, at the pending-stop sweep end: byte := 0, RcrdDisp `Off`; the full box (`0x573e38`/`0x573e24`, flags 0x40) when `+0x98`; TStrIpDlg; `push 0` at `0x573d04` and `call 0x408c44` at `0x573d06` (the same call that precedes the unsaved prompt at `0x575870`; its MessageBeep identification is inferred [I] and nothing is ported for it); Properties ShowModal (`0x5b59d4`, `0x573d14`), whose result in EAX is overwritten at `0x573d1a` without a test; the Save question (`0x573ec0`/`0x573f4c`, flags 0x23). Result 6 calls `0x56b36c`; any other result enables main+0x468; result 7 shows `[0x5b5d84]` (TPlsrAnalysisForm1) and calls `0x476f40`.
- **E5 Timer append** [S] `0x574b6d..0x574b82`: after the main and child frames of each batch iteration, the triple is appended only while the byte is still set. A finish in the main frame clears it, so that iteration and the later iterations of the batch append nothing.
- **E6 Bounded append** [S, I] `0x56a92c..0x56a963`: `+0x96` or `+0x97` set → clear and drop the sample; last index `+0x84` < 0x640 → insert; otherwise `+0x98` := 1. With only the captured mutations that admits 1601 triples (static conditional deduction, RC-REC-07); the box literal says 1600.
- **E7 TStrIpDlg** [S, D, I]: DFM ActiveControl EditStr, OK bkOK (TabOrder 1), Cancel bkCancel (2), BorderIcons []. FormShow `0x5252d4` sets the edit, caption and label from `+0x370/+0x374/+0x378`; OKBtnClick `0x525308` stores the edit text in `+0x370`. The caller seeds the caption `0x573e70`, the label `0x573e94` and the name from data+4, calls `0x43c450(EditStr, 40)` (read as MaxLength: inferred) and copies back ShortString[40] only for result 1 (observed).
- **E8 Activation** [S] (PLR-ACTIVATE-01) and **E9 Load prompt** [S] (PLR-LOAD-PROMPT-01): see the Pulsar provenance.
- **E10 'No Data'** [S] `0x56b7c9`: the name equal to ShortString `0x56b9bc` makes PrepareNoData write 0.01 into the data interval and a 4 s window; a second compare at `0x56bf11` is in an uncaptured draw path.
- **E11 Row tail** [S] `0x570e77..0x570ed2` (MEASUREMENT-ORIGIN-GATE): with `+0x96` = 0 the jump at `0x570e85` skips the `,"file"` suffix to `0x570ec5`, and the existing line is appended at `0x570ecd`.
- **E12 Properties OK** [S] `0x5719c0..0x5719c5` (HEADER-PROPERTIES-CLOSE). The complete 6-byte THdrDisp OkBtnClick method is `call 0x47a008; ret`; the 8-byte wrapper `0x47a008` is `xor edx,edx; call 0x475600; ret`. Neither of these two observed routines stores a ModalResult directly; the transitive helpers `0x475600`/`0x45e1b4` are not closed, so nothing is claimed about a store inside them. The frame does not test the ShowModal result (E4, `0x573d14`/`0x573d1a`), so the web OK closes Properties and opens the Save question with no result value. No Show/Hide name, ModalResult value or runtime behavior is claimed for `0x475600`/`0x45e1b4` (B4).

## Web decisions

- **WEB-REC-OWNER** [W]. The App owns one current dataset (`PulsarCurrentData`): the data (a .PLR file, a memory recording, or the cleared header left by the erase), a `generation` that increases on every dataset change, at most one capture lease, and the analysis window's reported modal/read activity. Page lifetime only.
- **WEB-REC-TXN** [W].
  1. Arming starts only with no analysis modal session or pending read and no lease. Otherwise it is refused with its reason and nothing changes.
  2. The erase OK, the plain arming and the No → erase answer re-check the generation from the Record press and the analysis activity atomically with the clear and the lease. A mismatch refuses: nothing is erased, Record is off.
  3. While a lease is held, the analysis Load control is disabled with its reason, a change delivered to it anyway is refused before any read, and a late import commit is refused visibly (`capture-lease`). The lease phases are `armed` → `receiving` → `finishing` → `committed`. The Identify answer commits the capture once and the lease stays `committed` through the modal Properties and the Save question, so no import can replace the capture before the Save answer, even with the radio route hidden. Save **No** releases the lease exactly once and then opens the analysis (Load enabled); Save **Cancel** (or Escape) releases it once. A second commit, a phase change after the commit and a second release are refused and change nothing. `committed` is a web transaction phase, not a recovered native flag; it rests on E4 [S] (the Identify → Properties ShowModal → Save question order) and the inference [I] that the VCL modals keep the analysis Load out of reach until the Save answer (no runtime witness, B3).
  4. Each import records the generation when its read starts; a commit after a dataset change is refused visibly (`superseded`). The existing read cancel/supersede epochs are unchanged. (The analysis already cancels a read when its route is hidden, so a read cannot overlap a Record press made on the radio route.)
  5. The analysis adopts a newer generation only while active with no modal session (Record, Clear, Review, Load prompt, Export, including an Export session kept closed while the analysis route is hidden) and no pending read; otherwise a "newer data waiting" note keeps drafts, the Review working copy and the confirmed list.
  6. Receive while armed moves the lease to `receiving` (the card says the capture will replace the current data); the descriptor itself is not changed then.
  7. Closing the main receiver after Receive started under the lease commits the rows recorded so far as the current data, with no Identify, Properties or Save, and then releases the lease (one commit, one release). Closing it before Receive releases the lease; the recording byte stays set until the next FormCreate clears it, as natively. While a finish dialog is pending the main close is refused, so the Save answer is the only end of a finish. Empty (0-row) and `No Data` captures follow the same commit/release order. The status names the partial commit only when the close requested it; a close before Receive reports only the closed window.
  8. [W] Defensive disposal: if the receiver workspace unmounts, it releases only the lease its own session still holds (by id; another owner's lease is refused and unchanged). The App never unmounts the workspace, so this is checked by review only, with no App witness.
- **WEB buffered commit** [W]. The descriptor changes only at the arming erase, at the capture commit (the Identify answer, or the main receiver close) and at an import. Natively the shared object's header is written at Receive and rows are appended on each tick. The commit publishes the data but does not end the lease (WEB-REC-TXN 3).
- **WEB-REC-BATCH** [W]. The finish dialogs appear after the synchronous tick batch ends. This is a declared adaptation of VCL modal reentry: natively ShowModal runs a message loop inside the main frame, and other timers (the Clocktimer reassociation changing source, offset or inSource; slews; paints) can run before the remaining child frames and batch iterations and change their signals and the Poisson draws. **No RNG interleaving or modal-order equivalence is claimed, and it is not claimed that only painting differs.** Kept: the recovered sample order, no draws added by recording, and the exclusion of the finishing main frame.
- **WEB-REC-CAP** [W]. 1601 triples (E6 deduction, labelled so); the box text is shown verbatim with a note on the discrepancy. Neither number is claimed as a verified native runtime result.
- **WEB-REC-STOP** [W]. Stop stays deferred to the sweep boundary. From a sweep that starts at position 0 with no intervening source refresh, frames 1..399 append and frame 400 finishes and is excluded (399 rows); a sweep that does not stop appends 400 rows. The first frame after Receive (position N + 1) wraps and appends, and a coupling refresh can reset the position, so no general "400 points" result is claimed. Stop before the first tick gives an empty capture (0 rows).
- **WEB-REC-ID** [W]. Identify admits 0..40 printable ASCII characters; longer or other text is refused in the dialog, never cut (the date dialog's policy). Enter is OK and Escape is Cancel (the bkOK default / bkCancel cancel semantics are inherited VCL behavior, inferred); there is no close box. A `No Data` name is accepted, as natively, with a warning.
- **WEB-REC-SAVE** [W]. Yes is disabled with its reason in the unsaved prompt, the Save question and the analysis Load prompt (the Clear precedent): the `0x56b36c` caller has been read statically (R-RX14), but its dialog, file naming and question are not ported, and a native save would mark the data as written. The reason points to the separate analysis verified Save ([PULSAR-SAVE-VERIFIED.md](PULSAR-SAVE-VERIFIED.md), R-RX15), which marks the data as written only after an exact read-back, and to the analysis download ([PULSAR-RAW-EXPORT.md](PULSAR-RAW-EXPORT.md)), which never changes the saved status. No and Cancel take their recovered paths. The native default button Yes is unavailable, so the declared web default is Cancel; the erase prompt keeps the native default OK.
- **WEB-REC-NODATA** [W]. Data named `No Data` stays current but the analysis does not present it (E10 overwrite plus the uncaptured `0x56bf11` branch). Data with no rows shows the recovered `No Current Data to Analyze` text as a non-modal alert and no panels or Properties.
- **WEB-REC-MEM** [W]. The memory recording has origin `memory`, a capture id, no bytes, file name, lexemes or line ending, no imported exact-byte download (**Download original recording bytes**) and no SHA-256. Its samples are the receiver's binary64 signals copied once into a Float64Array (no text serialisation, rounding or reparse). Recorded receivers' frequencies and gains are the header cells (raw gain products, no import zero replacement). Absent receivers keep their previous known header cells (from the file or capture that was current at arming) or null when never written. Properties shows `Data Not Written to File` until an R-RX15 verified copy of this capture exists, then the browser basename of that copy ([PULSAR-SAVE-VERIFIED.md](PULSAR-SAVE-VERIFIED.md)); any dataset change drops it. Record rows have 11 columns; Review shows the file column blank; the comment-only Edit applies only through its existing literal parse/rebuild, capacity and ASCII checks. Measurement rows recorded on a memory capture can be exported as 11-column rows by the analysis Export ([PULSAR-RESULTS-EXPORT.md](PULSAR-RESULTS-EXPORT.md)); that Export does not write the capture samples. Since R-RX14 a fresh rounded web .PLR copy of the samples can be downloaded under a fixed name, only through the analysis **Download capture as .PLR** ([PULSAR-RAW-EXPORT.md](PULSAR-RAW-EXPORT.md)). That copy is a separate artifact, not a save: the memory data keeps its full values and the download does not change its saved status (R-RX14: it stays unsaved, `Data Not Written to File`, the same generation; since R-RX15 an existing verified copy is kept). Panel labels use fixed2 frequency. A panel with a never-written gain draws the baseline and refuses a horizontal reading (`channel-unrecorded`). Nothing is filled from the catalog.
- **WEB-REC-HEADER** [W]. The header seed is the current dataset's header at arming (after the erase the header cells stay). An imported stored gain 0 was already replaced by 1 at read; memory gains are never normalised.
- **RC-REC-09** [S]. While receiving armed, Vert/Freq/Incr are disabled on the main and the children; Record is enabled only while the main timer is off.
- **Flags** [W]. The native 0x96/0x97/0x98/0x99 bytes are represented by: file data (0x96 = 0x97 = 1), memory data (0x96 = 0, and 0x97 = 0 when the capture is committed), cleared data (0 and 0), `full` (0x98) and the generation change (0x99). The web counterpart of a native write's 0x97/0x9a stores is the separate R-RX15 verified-copy receipt ([PULSAR-SAVE-VERIFIED.md](PULSAR-SAVE-VERIFIED.md)). The analysis activation's `0x5db := 1` store is not ported (the web does not model that store), and no exact VCL activation order is claimed.
- **Not ported**: the Save wrapper `0x56b36c` and the native writer with its state stores (+0x97, +0x9a); since R-RX15 those stores have a separate web counterpart (the verified-copy receipt), which is not a port of the writer; the web raw download (R-RX14) is a separate export, not a native save; MessageBeep; main+0x468; `0x476f40`; the analysis captions `0x56aec0`/`0x56aed4` and form `+0x5cb`; the VCL effects of `0x475600`/`0x45e1b4` (E12); the record label colours; audio (native audio is not reproduced; the R-RX13 trace audition is a separate web sonification of the stored trace, [RADIO-RECEIVER-AUDITION.md](RADIO-RECEIVER-AUDITION.md)).
- **Numerics, GDI, locale**: binary64 throughout, no Extended→Double store emulation, `.` decimal separator, English button captions, no pixel parity.

## Barriers

- **B1** `0x56b36c`: its body was read statically for R-RX14; at R-RX14 its literals, the dialog properties and the helpers `0x492708`/`0x40b224`/`0x40b514` were not bound. R-RX15 decoded the literals and recorded static facts for `0x492708`, `0x40b224`, `0x40b514` and the dialog class ([PULSAR-SAVE-VERIFIED.md](PULSAR-SAVE-VERIFIED.md)). The native dialog options, defaults, delivery and path state are not observed, so all three Save-Yes buttons stay disabled. The web verified Save is not their reentry.
- **B2** the complete draw routine containing `0x56bf11` and its `0x56b9bc` operand binding (start inferred at `0x56bacc`, not verified).
- **B3** VCL modal reentry order: no runtime witness, so the batch deferral stays declared.
- **B4** `0x56aec0`/`0x56aed4`, form `+0x5cb`, main+0x468, the body of `0x476f40`, and the transitive VCL/window effects of `0x475600` (from the Properties OK via `0x47a008` with EDX 0, and from `0x47a010` with DL 1) and `0x45e1b4` (`0x47a010`). The OK handler itself is observed (E12).
- **B5** the runtime 1600/1601 result.
- **B6** x87 Extended parity of the header cells and the stored triples.
