# Pulsar Parameters reference utility (Radio route)

Status: **bounded reference utility**. It ports the TPlsrDataForm1 window (VMT `0x56871c`) and its Find dialog TSearchInput1 (VMT `0x5682f0`) over a catalog the learner loads into memory. Since R-RX6 its Open is an explicit web reference adaptation that only reads the receiver session's shared `+0x5f7` source buffer (Receiver Open and the clock reassociation write it), and the window mirrors the catalog owner's shared list cursor that the receivers' picker moves (PP-05, PP-11). TRadioLab.PulsarList1Click (`0x567f80`, PP-10) is modelled as a pure session action with no UI caller: the native menu item's runtime availability is unproven (see PulsarList1 availability). It is not a receiver, acquisition, measurement or timing tool. It does not complete Radio I06/I07/N07/E06 or any inventory capability and claims no original-runtime or scientific equivalence. Provenance: `RADIO-PULSAR-PARAMETERS-PROVENANCE.json`.

Evidence tags: **[S]** static listing of CLEA_VEO.exe (SHA-256 `781bc970…c54c`) from the dossier `analysis/radio-pulsar-parameters-20261024` (31 manifest files, five addenda) · **[D]** DFM resource text · **[I]** analyst inference · **[W]** web policy. There is no original runtime proof. Excluded and not used: the TRadioLab metadata file, the RA-12 field-role file, the G2 receipt and any field-role claim derived from them, and the historical compiled-Find-mode assertion in `RADIO-ANTENNA-PROVENANCE.json`.

Modules:

- `src/core/radioPulsarParameters.ts`: pure state and numbers (no React, I/O or clock): pointer, shown record and shared-cursor mirror.
- `src/core/radioPulsarList.ts` (R-RX6): pure picker end cursor `pulsarPickerCursor` and live-buffer seed `pulsarSeedFromBuffer`; it writes nothing.
- `src/core/radioPulsarReferenceCatalog.ts`: pure web admission adapter (tokens, identity).
- `src/core/radioReceiverSession.ts` (R-RX6, additive): the read-only gate `receiverBoxRefusal` used by Open; the modelled `overwriteReceiverSourceBuffer` (action `'pulsar-list'`, on top of the unchanged `overwriteSourceBufferFromPulsarList` of `radioReceiver.ts`), tested but with no UI caller.
- `src/components/RadioPulsarParameters.tsx` (+ `.css`): host hook, window card, Find dialog and box; the Open refusal order and the notes.
- `src/components/RadioReceiverWindows.tsx` (R-RX6, additive): read-only API `sourceBuffer`/`boxRefusal` and the `onSourcePicker` callback.
- `src/components/RadioTelescopeRoute.tsx`: renders the card after the date card, joins the modality gates and wires the receiver API and the picker callback.
- Unchanged in behaviour: `radioPulsarCatalog.ts` (codec), `radioPulsarSelect.ts` (picker) and `radioReceiver.ts`. The header of `radioPulsarSelect.ts` still names "the Pulsar Parameters Open seed" as the picker's only consumer; that comment predates the receivers and is stale: the picker's callers are Receiver Open and the clock reassociation (and the modelled PulsarList1Click), never the web Open.

## Web policies [W]

- **WEB-PP-SRC-01 Local admission.** A browser file chooser; size check (above 1 MiB refused before reading) → `arrayBuffer` → `resourceSha256` → `parsePulsarCatalog` (unchanged codec) → commit. Memory only: nothing is uploaded, bundled, copied or persisted. The original's automatic path, failure box (`0x564d08..`) and conditional quit request are not reproduced.
- **WEB-PP-SRC-02 Identity.** File name (≤ 128 characters, text only), bytes, SHA-256, record count. Equal SHA-256 *and* size to the recorded `Pulsars.dat` (`ba94ee94…ceaa`, 285 692 bytes) is labelled "matches the recorded bytes", which identifies bytes, not runtime authority; anything else is a user-supplied reference catalog. The original file is not one of the 1279 resources.
- **WEB-PP-SRC-03 Lifecycle.** Each read has a token. Cancel button, route hidden, project operation, page hidden and unmount cancel it; every await re-checks token and gates. Invalid, too large, read error, cancel or a late completion keep the previous catalog and identity. Loading is refused while the window is open; Open is refused while a read is pending. Reimport of the same name replaces catalog and identity together.
- **WEB-PP-OPEN-01 Open.** Available once a catalog is admitted and no read is pending. It is an explicit web reference adaptation, not a delivery of PulsarList1Click: it keeps its authored label, runs no picker and writes nothing (WEB-PP-LIST-01..03). The `PulsarList1` menu item's DFM facts are recovered (PulsarList1 availability) but its runtime availability is not (G9), so no native menu availability is claimed. A window is created (fresh Find memory) or reused (Find memory kept), then activation runs (WEB-PP-ACT-01). Another catalog object starts a fresh window.
- **WEB-PP-OPEN-02** Activation runs only at Open (G1).
- **WEB-PP-LIST-01 Entry and refusal order.** At the press, on the latest state (refs, so a dialog or box that opened earlier in the same task also refuses), in this order: the route is shown, no project operation runs and the page is visible (`inactive`); a catalog is loaded (`no-catalog`) and no read is pending (`reading`); the window's own Find dialog or box, an antenna dialog or box, the Set Date/Time, ID dialog or a foreign native `<dialog>` is open (`modal`); the receiver close box (`close-box-open`) or a Record prompt or finish dialog (`record-dialog-open`), read through the pure read-only gate `receiverBoxRefusal` on the latest session; after the antenna's first activation, a missing receiver session (`unavailable`, review-only: unreachable in the App). Only then the window opens and activates on the live buffer. Open writes no buffer, runs no picker and touches no receiver trace, RNG, lease, timing, Record or card-order state; a refusal also moves no cursor, pointer or window; no other surface or pending edit is cleared. The card being inert behind a surface is not relied on. Held Enter on Open does nothing more (`ignoreHeldKey`).
- **WEB-PP-LIST-02 Initial buffer.** [W] Before the antenna's first activation, and after it until Receiver Open or a clock reassociation writes the buffer, Open reads the initial buffer (no record), so the head; no picker runs and no pointing is read or invented. The note says the shared name was empty. Local JD is the radio scenario's reading or null, never the host date.
- **WEB-PP-LIST-03 Modelled PulsarList1Click (no UI caller).** The pure session action `overwriteReceiverSourceBuffer` models the native click as exactly `overwriteSourceBufferFromPulsarList` (limit 2) and is kept with its tests; no web control calls it, because the menu item's runtime availability is unproven (G9). As modelled: hit copies the record, miss clears only the J2000 name (the previous record stays behind the empty name). No receiver refresh, paint, title, trace, offset, pointer, seed, RNG, mark lease, Record byte, capture or card order changes at the click, and the persistent tick error stays. Admitted with or without receivers, while receiving, armed or capturing, with a stop pending or a persistent tick error. Later ticks may legitimately run the existing name coupling (rebuild and RNG draws when the name changed; a cleared name rebuilds from the stale record under an empty name); the title changes at the next parameter refresh; the Record header takes the buffer's legacy name at the next Receive. No future signal invariant is claimed.
- **WEB-PP-ACT-01 Activation.** The seed is the live buffer's J2000 name (null record or empty name → the head). Pointer, shown record and shared cursor are all set to the scan result.
- **WEB-PP-CUR-01 Shared cursor.** The window keeps `listCursor`, mirroring the catalog owner's cursor, which only this window can show. Receiver Open and the clock reassociation report each committed picker run (a `source-hit` or `source-miss` event) synchronously, with exactly the catalog and pointing that transition used; the window then takes `pulsarPickerCursor(catalog, pointing)`, also while Find or a box is open (the timer keeps firing under a modal) and while the route is hidden. Nothing is redrawn: the pointer, the shown texts, pending edits and the boundary status stay. A different catalog object is ignored (defensive; unreachable, the catalog is locked while receivers exist). Picker runs before the window exists are not observable (activation resets and rescans).
- **WEB-PP-OWN-01 Ownership.** The window owns its frozen catalog reference, the pointer (form+0x45c), the shown record and the shared-cursor mirror. The buffer is the receiver session's (`bank.sourceBuffer`), written only by the receivers (Receiver Open and the clock reassociation) and read at activation and Find activation. Nothing writes the antenna, the clock scenario or any receiver field.
- **WEB-PP-CLK-01 Clock.** At Open and Reset the local JD is the radio clock scenario's reading (`readRadioClock`, WEB-CLOCK-01) when it is `ok`, else `null`: Date and Period stay empty with a note. No host `Date.now()`, no `0x5bad48`/observatory offset; the read has no side effect on the scenario.
- **WEB-PP-EPOCH-01** 2400000 everywhere. `J − 2400000` is the textbook MJD + 0.5; the half-day offset to the catalog's PEpoch column convention is kept, not corrected.
- **WEB-PP-UPD-01 Update.** Blank keeps the prior value; whitespace only is an error; grammar `parseDelphiFloat` (32 characters, exponent ≤ 2 digits). Edits longer than 32 characters are refused, not truncated (the DFM sets no MaxLength). A Date error stores nothing; a Density error after a good Date keeps it, leaves texts and stale derived texts, keeps Update enabled and opens the box.
- **WEB-PP-UPD-02 Domain.** No exception path: a fixed echo needs `|v| < 1e15`; a zero or non-finite density, a non-finite quotient or a rounded distance that is not a safe integer, and a period with `|p| ≥ 1e15`, show an empty field with an "outside the OpenVireo numeric domain" note. No value is invented.
- **WEB-PP-NUM-01 Numbers.** binary64 in the listing's order; Singles are already `Math.fround` from the codec. Rounding: `roundHalfEven`, a bounded policy consistent with the compiled control-word cell `0x5ae024 = 0x1332` (addendum COMPILED-CW-CELLS). That cell is a mutable global and the runtime word at `0x5691ef` is unknown; no x87, `StrToFloat` or locale parity. Native stores local JD and density as Extended (form+0x448/+0x452); the web keeps binary64 [W]. At JD ≈ 2451545 binary64 spacing is 2⁻³¹ ≈ 4.66e-10 day (≈ 40 µs), below the 1e-8 day shown by the 8-decimal Date, so that precision is not inherently unsupported; formatter rounding at decimal boundaries and runtime CW/x87 equivalence remain unknown (G4, G6).
- **WEB-PP-FMT-01** `formatFixed`, `formatExponent(v, 5, 2)` and the `0x486bc0` port `skyCoordsFieldsFor`; the identity of `0x40cf28` is not asserted; separator `.`.
- **WEB-PP-NAV-01** `MessageBeep` becomes a polite status line naming the shared list cursor ("the shared list cursor is at the last record…; nothing moved"); no audio, no box. It can appear while another record is shown. "Record n of N" is web text.
- **WEB-PP-FIND-01** Draft bound 64 characters (longer edits refused); commit takes the first 12 code points unchanged; literal, case-sensitive substring with a non-empty query. Escape = Cancel; Enter in a field = OK (DFM `Default=True` on OK).
- **WEB-PP-FIND-02** (′, R-RX6) The cursor is saved at OK, after the dialog returns, not when it opens. Hit: pointer, cursor and shown record := the hit, displayed. Miss: pointer and cursor := the saved cursor, without redisplay (shown texts and pending edits stay); Update/Reset then compute for the pointer record. Without a receiver association the saved cursor is the shown record, so the record shown before Find is kept. Cancel commits nothing and does not undo a cursor move made meanwhile. Authored not-found wording, labelled as such; the recovered literal text (PP-08) is not shown.
- **WEB-PP-FIND-03** env+0x37ce has no web owner; the first-open mode is the explicit web choice 1 (B1950). No compiled default is claimed.
- **WEB-PP-FIND-04 Live seed.** An empty stored query is seeded at Find activation from the live buffer, gated on its J2000 name being non-empty in either mode (a cleared name never gives the stale B1950 name). A non-empty stored query and mode are kept on reuse, lost on Exit.
- **WEB-PP-KEY-01** Enter in Date/Density runs Update only while it is enabled; a held Enter does nothing more. [I] In every reachable state Update enabled implies Default true (edits set both, Reset clears both, display only disables), but VCL key delivery is not claimed.
- **WEB-PP-EXIT-01** Only File ▸ Exit closes the window (the native close-box path is unverified). Exit drops the window and Find memory; focus returns to Open.
- **WEB-PP-PRES-01 Presentation.** The window is a non-modal card. The Find dialog and boxes are application-modal: the rest of the route and the App header/toolbar are inert, Tab is trapped, Escape consumes only the topmost surface. They are presented only on the active route, outside a project operation, without a foreign `<dialog>` and without an antenna surface; otherwise they keep their state unpresented and move no focus. An antenna box arriving while Find is open is presented instead; Find returns afterwards with its draft. Focus: Open → window heading; Find → name field (selected); OK hit/Cancel/Escape/miss box → "Find Pulsar..."; update-error box → the failing Date or Density field; Exit → Open. Disabled, hidden or inert targets are never focused.
- **WEB-PP-PRES-02 Notes.** "Record n of N" names the **shown** record. When the shared cursor differs from it, a note says that Prev/Next continue from record k (name), moved by the receiver's source association; Prev/Next are described by it. When the pointer differs from it (after a Find miss), a note says that Update/Reset compute for record k (name) and the shown record was not redrawn; Reset/Update are described by it. The Open note (`data-seed` `name` or `none`, from the window's seed) names the shared source name the last Open read, or says it was empty, and that Open did not change it; it names no picker. The notes are plain text, not live regions, and redraw nothing; they wrap at 320 px. An Open refusal is a polite status naming the gate.
- **WEB-PP-HELP-01** Help shows authored web help, labelled as not the original Help file; no HLP text is copied (G7).
- **WEB-RX-CAT-01 Receiver lock.** The silent receiver monitor ([RADIO-RECEIVER-MONITOR.md](RADIO-RECEIVER-MONITOR.md)) reads this reference catalog at Receiver Open and at each clock reassociation. Load is refused (`receiver-open`, disabled with a reason) while any receiver window exists, and Receiver Open is refused while a read is pending. R-RX6 supersedes WEB-RX-PP-01: the window reads the receivers' buffer and mirrors the shared cursor (WEB-PP-LIST-01, WEB-PP-CUR-01).
- **WEB-PP-SAVE-01** Save investigation excludes the catalog, identity, window, local edits, the shared buffer and the cursor (visible note); reload empties them. No storage, IndexedDB, Worker or network. Audio, Add Current Item and the Save writer stay out.

The cursor model is complete **only relative to the ported flows**: the catalog consumer `0x567aa5`, the excluded Save writer region and the ClocktimerTimer callbacks `0x56588c`/`0x561e88` are not ported and no cursor move is invented for them. An activation or Find scan without a hit is covered by PP-05/07 and PP-08.
