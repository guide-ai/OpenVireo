## Recovered expression and order

Point addition `0x5245d0..0x524a41` derives a base-scale reference peak and exposure/base-exposure ratio upstream. This kernel takes those scalars explicitly. It does not invent a photometric calibration or normalize the resulting pixel sum into an assumed total photon flux. Projected pixel positions are not RA/Dec or supplied FITS WCS. Shared source initialization uses CCDpixel sizes for both camera callers;automatic camera/profile/magnitude mapping is not added here.

1. The support integer starts3 and grows while `exp(−r²/2) × referencePeak > 1`. It is independent of exposure scale. Center coordinates and support radii use native FISTP;the port declares nearest/even conversion. Gaussian visits cover the rounded support rectangle,clipped to the raw plane,ordered by increasing row then column. Mean is `exp(−rho²/2) × (exposureScale × referencePeak)` using the supplied unrounded position and two scale axes.
2. A second pass spans four times those radii. It visits the thin cross `abs(dx)≤3 OR abs(dy)≤3`. When the xdistance is0/1/2/3,it sets a ratio from ydistance with multipliers1/Extended1.4/2/4. When the ydistance is0/1/2/3,it **overwrites** the ratio from xdistance. The result is asymmetric near the center;ratio≤0 skips without drawing. The port preserves this order instead of making a symmetric PSF.
3. The captured spike expression is `exp(−ratio)² × (exposureScale × (Extended0.01 × (exposureScale × referencePeak)))`. It contains exposure scale twice. That static expression is retained;no original runtime witness proves a native bug or authorizes a linearized replacement.
4. Every visited contribution uses the recovered scalar jitter and stores **Single after each addition**,including repeated visits to the same pixel across the two passes or multiple sources. Small/zero-rounded contributions still consume their supplied uniform. Negative jitter contributions are retained;no Poisson/Gaussian noise substitution or nonnegative flux clamp is introduced.

The native point route does not update the initial owned histogram. The wrapper retains that exact histogram object from the background phase while returning a new immutable pixel array. It does not reconstruct original statistics from the resulting image.

This is not native exp/x87/control-word/GDI parity. Unsupported zero-radius geometry and nonfinite inputs are rejected. Dimensions1..1024 per axis,coordinates within±1e6,positive scale axes≤1024,reference peak0..1e12,exposure scale0..1e6,and65536visits bound the mathematical API. These are explicit web admission rules,not native error/overflow equivalence or new allowed native camera configurations.

The plan and its ordered indices/means are frozen. Applying a plan requires a matching finite Single background/point phase and exactly one finite `[0,1)` uniform per visit.
