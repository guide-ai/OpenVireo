## Recovered contract and independence

Binary: VIREO1.504, SHA-256 `781bc9704b4674038267834a9ed21d502c455378d8fc9eb15a1653e20c52c54c`. [Running-clock provenance](../data/observatory/running-clock-provenance.json) pins original binary/license hashes, eleven raw ranges, original constants and an independent Decimal100 reference. [48 numerical scenarios](../data/observatory/running-clock-vectors.json) evaluate the complete forward-projection/drift/inverse composition with Taylor cosine and signed RA normalization. They are mathematical checks, not original observations or runtime traces. Raw research remains outside source at `/home/dobleuber/Documents/Codex/2026-10-18/task-3/running-clock-recovery/`.

- **RC-C01, `0x5384d6..0x53852e`:** the native callback rebuilds date from host time plus a fixed environment offset, then obtains the selected-site sidereal reading. The callback counter controls display refresh every ten deliveries; it is not an elapsed-time scale. The port samples an explicit UT anchor plus monotonic browser milliseconds at1:1 speed. Native local-host offset/date and wall-clock adjustments remain unported; this is an explicit browser time adapter.
- **RC-C02, `0x5385e0..0x5386ae`:** native hour angle is sidereal hours minus stored RA. When tracking/moving flags are active, the callback updates the hour-angle field and retains RA/Dec. In the stationary, untracked branch it calls `0x53cb6c`. The preview admits these stationary tracking-on/off branches; finite-duration motor/slew states are not invented.
- **RC-C03, `0x538768..0x5387e6`:** DriveBtn toggles the tracking flag when not moving. Turning it off records host time and the current projected displacement as the new drift baseline. The browser samples/reanchors the current committed preview position when toggling; a normal running clock continues. Imported state never restarts a timer.
- **RC-C04, `0x53c9d4..0x53ca53`, `0x53cb6c..0x53ccd2`:** the cached x displacement is `centerX−projectedX`. Nontracking adds `(hostNow−baselineHostTime)·24·cos(decRadians)·scale`, where host time is in days and the literal Single at`0x53cce0` is24 (`0000c041`). It then uses `centerX−displacement` as the inverse-projection input.
- **RC-C05, `0x5949c8..0x594a3c`, `0x594a44..0x594b03`, `0x594b40..0x594b8d`:** forward scale is `width·15/fieldDegrees`; inverse x divides by that same scale and cosine. Algebraically the stationary fixed-declination composition reduces to `RA0 + elapsedDays·24`. The implementation evaluates that reduction from an absolute anchor instead of accumulating callback deltas. It does **not** replace24 with a modern sidereal-day coefficient. This is a declared analytical Number policy, not bitwise equivalence to native per-pixel Extended calculations.
- **RC-C06, `0x4bad9c..0x4badf7`:** normalize RA through signed fractional turns and add24 for negative results. At the 0/24 boundary, finite Decimal reference evaluation can land infinitesimally below24 while the analytical Number result is0; assertions compare circular angular error, within`1e−12 h`, rather than claiming identical branch bits.
- **RC-C07, `0x539290..0x5393c6`, constructor `0x5a2ae8` and option copy `0x5879b8..0x5879cd`:** compiled Options+`0x27cd` is0 and maps to Environment+`0x2e7d`; the native horizon helper returns true immediately in that branch. No instructor override is loaded here. Horizon enforcement/visibility is not advertised or synthesized. The separate±85° browser admission bound avoids the unresolved numerical cancellation at poles; it is not a native horizon.

The reference uses Decimal100 and original radian constants to reconstruct full projection, cosine, displacement, inverse and normalization for RA0/9.92588/23.9998, Dec0/55.68888888888889/−85/+85, 0ms/1s/1h/24h, and both original finder/telescope field widths. Tracked coordinates remain exact input values. Existing21 independent sidereal scenarios also remain in regression. Number/Math, browser cadence and explicit stop policy are adapters; no x87, GDI or native timer-equivalence claim is made.

## P02 and lifecycle

Full16 uses observing policy `OpenVireo-stopped-observing-workspace-v6` with strict `clockDrive`: applied UT, total elapsed milliseconds, anchor elapsed/pointing, tracking flag, policy and proof. Runtime monotonic anchors and a running flag are absent from files. Derived current RA must exactly match observing context, and base UT must match the fixed worksheet, before replacement. Unknown/cached/running fields, changed proof, invalid units, excessive time and legacy smuggling reject atomically. Existing twelve-archive, replay/event and file limits remain unchanged.

A clock scope is created only by explicit Start/tracking use. Backups without it retain their existing versions/bytes. Old1–14 lack fixed UT and preserve current clock time stopped, reanchoring to any restored preview coordinates. Old15 replaces its represented fixed UT; if that UT differs, an existing stopped drive rebases to the restored UT with zero elapsed and restored pointing. Otherwise it retains elapsed time and reanchors to restored pointing. Tracking mode is preserved in these legacy migrations. New16 replaces its complete validated clock scope. Legacy restore never enables a running timer or recalculates acquired photons.

The browser hook uses an absolute monotonic anchor, so callback partitioning does not accumulate time/RA rounding. It samples at a target100ms cadence and rejects a gap above1000ms before adding it. Save, navigation, visibility and user changes release it; ordinary tracking toggles reanchor and continue only if the current interval was safe. The 24h/declination/year bounds are browser resource/numerical limits, independent of telescope allocation credits or scientific exposure duration.
